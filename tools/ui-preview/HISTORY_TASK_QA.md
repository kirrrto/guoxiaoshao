# 历史浏览任务专项预览

在项目根目录执行：

```powershell
node tools/ui-preview/build.mjs --history-task-only --out "<工程外的专项输出目录>"
node tools/ui-preview/check-layout.mjs "<工程外的专项输出目录>"
```

此专项以当前历史页、我的页的 JS/WXML/WXSS 生成 **7 种状态 × 2 页 × 3 种宽度，共 42 个快照**。宽度为 320、375、430 像素。

- `history-member-reward`：会员进入历史页，任务增加 1 次；我的页显示完成和 +1 明细。
- `history-free-first`：免费账号初始余额为 0，首次浏览成功后增加到 1 次，最近浏览列表为空。
- `history-read-error`：浏览接口失败，历史页提供重新加载；我的页保留未完成状态，不出现奖励明细。
- `history-balance-cap`：余额达到 10 次上限，没有发奖；历史页说明原因，我的页显示“已浏览·待领取”，次数明细不虚增。
- `history-completed`：当天重复进入，返回已完成结果，保留一条 +1 明细。
- `history-longcontent`：三条最近浏览条件，使用长商品标题、不同日期和门店范围，检查换行。
- `history-loading`：浏览请求尚未返回，不提前显示完成或奖励明细。

沙箱为 `history.browse`、`quota.completeTask`、`quota.ledger` 提供相互一致的模拟返回。调用实际页面逻辑后再生成快照；最近浏览列表不包含受限库存数据。默认基础 90 场景也使用这些模拟返回，避免业务新增接口后出现不完整数据。

检查会保存 `layout-metrics.json` 和代表截图，包括历史页各状态的 375 像素截图、长文本及余额上限的 320 像素截图，以及免费首次浏览后“我的”页的 375 像素截图。

所有页面保留“离线模拟”标识，不联网、不修改真实账号、不增加真实查询次数、不发提醒。这些结果仅用于排版检查；奖励幂等性、真实账户同步和微信原生渲染分别需要业务测试及小程序验收。
