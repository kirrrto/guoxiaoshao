# 历史浏览任务专项预览

在项目根目录执行：

```powershell
node tools/ui-preview/build.mjs --history-task-only --out "<工程外的专项输出目录>"
node tools/ui-preview/check-layout.mjs "<工程外的专项输出目录>"
```

从 3.8.0 起，历史页保留为旧链接和已获奖励的兼容入口。此专项以历史页、我的页的 JS/WXML/WXSS 生成 **7 种状态 × 2 页 × 3 种宽度，共 42 个快照**。宽度为 320、375、430 像素。

- `history-member-reward` 使用已持有当天旧版浏览凭据的会员账号。历史页确认领取原有奖励，「我的」显示增加后的查询余额。
- `history-free-first` 使用从未浏览过历史的免费账号。「我的」显示剩余查询次数 0 和签到按钮。
- `history-read-error` 模拟读取最近浏览条件失败，历史页显示重试入口。「我的」仍显示当前查询余额。
- `history-balance-cap` 使用已持有当天旧凭据、余额为 10 的账号。余额卡显示 10，旧奖励另行提示当日用次后可领。
- `history-completed` 模拟当天再次打开历史页，显示已经领取，余额保持原值。
- `history-longcontent` 提供三条最近浏览条件，用来检查门店名称和时间的排版。
- `history-loading` 模拟浏览请求尚未返回，历史页显示加载状态。

沙箱预置当天旧凭据及已领状态，分别模拟 `history.browse`、`quota.completeTask`。历史页继续支持领取已经获得的旧奖励。所有「我的」场景都检查页面没有请求次数流水，查询余额取自当前账号。

检查会保存 `layout-metrics.json` 和代表截图，包括历史页各状态的 375 像素截图、长文本及余额上限的 320 像素截图，以及免费首次浏览后“我的”页的 375 像素截图。

所有页面保留“离线模拟”标识，不联网、不修改真实账号、不增加真实查询次数、不发提醒。这些结果仅用于排版检查；奖励幂等性、真实账户同步和微信原生渲染分别需要业务测试及小程序验收。
