```powershell

npm test
```

- `npm test`：后端事务、权限、并发恢复、调度、通知、前端交互及目录图片回归。
- `npm run check`：UTF-8、JS 语法、JSON、页面文件和 WXML 表达式检查。
- 离线预览从实际 WXML/WXSS 生成，用模拟数据覆盖不同宽度与状态；不调用生产云函数，不代表真机微信验收。

## 会员与免费使用

- 新用户余额为 0；默认每日签到 +1 次、浏览历史体验任务 +1 次；每日获得上限 2 次，余额上限 10 次。
- 免费实时查询和历史查询默认各消耗 1 次。全部上游查询失败会返还本次次数。网络结果不确定时，相同条件沿用原请求 ID，支持余额为 0 时恢复。
- 会员实时查询和历史不扣次数；最多关注 **3 个具体配置，每个配置最多 3 家门店**。容量或颜色不同分别占名额；暂停仍占名额，删除释放。
- 已配置的新品开售 30 天内，免费用户不可查询实时信息，只能查看昨天及更早的历史。新品窗口由运营按真实开售时间配置，不根据机型名称猜日期。
- 会员到期会停止自动关注和提醒，保留配置和剩余次数。
- 微信提醒需要额外订阅授权和服务开关；会员身份不等于无限提醒。
- **兑换码开通与付费购买双入口并存**。本次兑换活动为 30 天，每账号一次，大小写和首尾空白不影响校验；连续输错 5 次暂停尝试 15 分钟。服务端事务保证重复点击、换请求 ID 或网络重试不多领，会员到期后也不能重复领取本活动。付费入口显示「暂未开放」，不能通过运行配置单独打开未接通的支付。

## 主要修复

- 查询扣次、记录、退款和重试采用事务；查询编号绑定型号、门店和日期。
- 库存状态与事件原子提交，忽略迟到旧样本；首次发现、确认补货与中断后恢复分开表达。
- 关注、查询关注摘要及历史最近观测统一展示新鲜度：过期主状态为「待更新」，旧值标为「上次有效结果」；未知与缺少观测分别提示，不把旧数据显示成实时库存。读取列表不会生成新样本。
- 兑换、会员有效期和零金额订单同事务提交；后台配置也在事务内读取、合并和校验，并发修改公告不会覆盖已关闭的兑换开关。
- 手动查询和自动采集发现的补货都进入持久通知流程，支持规划失败恢复和并发去重。
- 历史提供稳定快照分页与全量统计，防止受限新品通过旧历史读取当前库存。
- 前端初始化失败可重试、结果卡重查绑定原商品、关注页可见时刷新，页面退出停止轮询。
- 产品图片按苹果官方 SKU/配色映射。目录同时保留图片来源；缺图或加载失败有固定占位。
- 管理员身份不再由“缺少 OPENID”直接认定；HTTP 入口关闭，客户端无法修改会员或余额。

## 源码结构

- `miniprogram/`：原生页面、共享选择器、会话缓存、操作 ID 恢复和精确商品图片索引。
- `cloudfunctions/gxs_api/lib/services/`：业务接口。
- `cloudfunctions/gxs_api/lib/repo/`：CloudBase 事务与共享事务业务逻辑。
- `cloudfunctions/gxs_api/lib/engine/`：调度、租约、持久事件通知和消费者小程序专用消息发送器。
- `tools/collector/`：常驻进程、健康检查、Docker 和部署参数模板；默认关闭业务请求。
- `catalog/`：全国门店和 SKU 目录；`tools/catalog/` 提供抓取、图片映射、验证和同步工具。
- `tools/db/export-plan.mjs`：生成可审阅的集合规则与索引计划，不连接云环境。
- `tests/`：离线回归。`evidence/`：来源和验证证据。
