# 会员兑换配置与验收

**1.0.1 发布清理版：** 当前工程直接使用真实微信账号，功能验收页与模拟运行时已从 `miniprogram/` 移除，旧的本地验收开关不会生效。无需先退出模拟，直接从会员卡打开兑换窗口即可。测试用模拟只保留在 `tests/helpers/`，不进入微信上传目录；[会员功能验收](MEMBERSHIP_ACCEPTANCE.md) 中原开发模拟章节仅作历史记录。

本次清理只修改前端；兑换继续使用已部署的 1.0.1 云函数，无需重复部署。付费购买仍保持关闭。

本次运营活动码由运营单独发放，不写入仓库文档。全活动共 20 个名额（`memberRedemption.maxClaims`，已兑换账号计入），名额用完后提示「本期兑换名额已发完」。用户在「我的 → 会员 → 兑换码开通」输入，前后空格忽略，字母大小写不影响兑换。

活动提供 30 天会员，每个微信账号只能领取一次；有效会员顺延 30 天。该码是本次可重复分发给不同账号的活动码，不是每人一个的单次卡密；知道该码的账号均可按规则领取。

服务端以活动标识 `launch_30d_v1` 与可信 `appid:openid` 保证领取幂等，和订单一起原子更新原有 `users.membership`。订单来源标记为 `redemption_code`；原始兑换码不进入订单或用户数据。

运行配置 `memberRedemption.enabled` 控制是否接受本活动兑换，默认启用。配置应经已授权管理端更新；停止活动不会撤销已领取会员。修改兑换码哈希但保留活动标识，不会让已经领取的用户再次领取；后续新活动需明确制定新的活动标识和规则。

连续输入错误会触发账号级限流：5 次错误后暂停尝试 15 分钟。错误码无效、活动关闭、尝试过频及网络未知结果均由前端给出明确说明。网络失败可重试同一兑换，不能由客户端直接增加会员时间。

## 上线验收

1. 使用真实微信账号进入体验版，打开「我的 → 会员 → 兑换码开通」。
2. 输入错误码，确认会员未变化且有可理解提示；输入正确活动码，确认有效期、查询不扣次、3 个配置 × 3 家门店权限同步更新。
3. 重复输入同一码，确认提示已领取，到期时间不再延长。
4. 已有有效会员领取时顺延；到期会员领取从当前时间重新计算。
5. 退出小程序再进入，会员仍由云端账号记录恢复；会员记录显示兑换来源。
6. 查看付费入口仍为暂未开放。本次不执行任何真实付款或自动续费。

付费方式后续通过正式支付成功回调完成同一账号的会员延期。前端支付返回、客户端自报成功或兑换输入均不能代替服务端核验。
