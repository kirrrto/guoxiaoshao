# 果小哨 v3.7.0 发布说明

2026-11-12 首次上传的 3.7.0 开发版为 1,117,600 字节。后续的超时、旧查询恢复、账号切换和提醒状态修复晚于这次上传。正式版尚未提审或发布。[GitHub #9](https://github.com/kirrrto/guoxiaoshao/pull/9)

## 用户更新

- 查询结果按门店展示货号对应的取货状态与观测时间。切换配置或门店后，保留的上次结果标明自己的目标。
- 我的小哨突出下一次计划提醒和库存关注。授权充足时可以先看库存，需要处理授权时可以直接进入。
- 历史记录按实际时间排列，同一秒的多家门店各自显示状态。会员身份、果哨标志、有效期和名额共用账户卡的底色。到货和断货的授权次数分别显示。[页面前后对照与验收](../evidence/design/3.7.0/README.md)

## 查询、账号和库存可靠性

- 用完最后一次查询额度时，如果响应在网络中断时丢失，恢复同一账号、配置和门店可继续上次请求。回归核对了冷启动、换门店、换账号与原请求号，恢复路径只扣一次。
- 切换账号时分别维护余额和额度版本，迟到的旧响应不会盖掉新账号的余额。
- 时间戳超前、过期、顺序矛盾的观测按待确认状态展示。采集状态缺失时，查询、历史和账户页面仍可打开并说明当前状态。[功能验收与回归范围](../evidence/verification/3.7.0/functional-reliability.json)

## 首次上传后：3.6.0 超时与扣次审查

维护者提供的报错有两种堆栈写法，去重后是三个事件，分布在 iOS 与 Android，均为微信 8.0.80、基础库 3.17.6。原版 `WACloud.js` 的两处列号位于同一段网关错误处理代码。按账号和时间窗口核对到 9 次成功调用；最长一次账户初始化网关耗时 11.681 秒，函数耗时 286 毫秒。错误样本没有请求号，无法把附近任何一次成功调用判为出错调用。

- 安全读取收到微信原生超时后可重试一次；本地等待期限到达时，不另开一笔仍可能在执行的请求；切换账号会撤销旧账号排队的重试。仅打开攻略或已知断网时，不主动启动鉴权。
- 付费查询超时保留原请求号。旧版遗留请求先核对账号和原目标：已存在的查询恢复原单；没有匹配记录时，新扣次必须确认，且不能超过确认的额度。翻页继续原单，不能为另一账号创建查询。
- 消费者端每次实际发往 `gxs_api` 的请求都有独立的诊断编号，客户端失败日志和云函数入口通过该编号对应。日志只增记动作和编号，不写入请求内容或用户身份，不增加数据库读写或云调用。客户端与 API 都更新后才有两端记录。
- 另修复账号切换后的余额刷新、签到成功反馈、断货授权用尽时的补充入口，以及深色模式下商品缺图提示的对比度。
- 开发者工具报「在项目根目录未找到 app.json」时，核对实际导入目录和本地配置覆盖。已在原工程恢复模拟器启动；源码检查现在也按开发者工具配置解析并核验入口。[工程导入说明](../README.md)

四个被点名页面的编译产物均无 `channel-video`；独立空页在三版官方基础库中都能复现这项告警。保留[组件编译证据与微信复核步骤](WECHAT_CHANNEL_VIDEO_3.7.0.md)。按线上限额做的[离线容量对照](../evidence/verification/3.7.0/capacity-offline-comparison.json)中，300 人各查一个不同目标均成功，各查三店时未能全部完成，未向生产发起压力测试。

本次[回归记录](../evidence/verification/3.7.0/runtime-retest.json)对应修复后的源码。上线由维护者处理：先部署并核对新版 `gxs_api`、核验同步生成的监控包，再上传相同源码的小程序；旧 API 不识别恢复操作时会安全失败，不能回退成新的扣次请求。没有数据库结构迁移。若回退，保留用户的原请求记录和账本。正式发布前仍需在新上传的包上完成[微信云测](https://minitest.weixin.qq.com/cloudtest/)的四项[质检](../config/wechat-quality-findings.json)，并单独完成手机实收及[生产容量与时效验收](../config/delivery-targets.json)。
