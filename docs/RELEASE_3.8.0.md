# 果小哨 v3.8.0 发布说明

本版可以在微信体验版验收第三个入口「其他站点」。选择日本、台湾或香港后，可按当地门店查询 iPhone 18 Pro / Pro Max 的自提状态，会员还可以保存关注、订阅微信到货提醒。大陆查询仍是首页。三站能力默认关闭，正式开放前需完成云端部署回读、逐站观测及真机收信。

本次消费端源码指纹为 `sha256:cad1908ad9cd2f0b78fabd6a47190e073fa5b6b91c5fa82da1c34541724c9a8e`，供上传后关联微信质检报告。

## 用户能做什么

- 在「其他站点」选择地区、机型、颜色、容量和直营店。手动查询显示所选门店的结果与当地观测时间，东京为 UTC+9，台北及香港为 UTC+8。超时和缺失数据会提示无法确认。重查失败时，上一次有效结果单独标注时间。
- 会员可以直接关注配置和门店，查看、暂停、恢复或取消已存关注。大陆和其他站点共用会员名额。切换界面语言与切换地区相互独立，此页提供简体中文和英文。提醒按关注所绑定的语言和对应的微信授权发送。
- 第三个原生底栏入口取代原「历史」。从旧链接进入的用户仍能查看历史，原来已经取得资格的用户可以领取当日待领奖励。既有关注、订单和库存观测沿用原数据。
- 其他站点在手机上先选配再看结果。可用窗口达到 900px 时，左侧选配、右侧查看取货结果和关注列表。

## 目录与库存

本版收录日本 11 家、台湾 2 家、香港 6 家 Apple 直营店。两个机型分别有 4 种颜色和 4 种容量，每站 32 个当地货号。门店号来自对应零售门店目录，货号逐项核对当地购买页的配置数据。补充现有系列或新增机型时，应在对应站点重新核对。 [日本门店](https://www.apple.com/jp/retail/storelist/) · [台湾门店](https://www.apple.com/tw/retail/storelist/) · [香港门店](https://www.apple.com/hk/retail/storelist/)

三站的商品图按机型和颜色复用包内已有的 8 张配图。容量和地区不增加图片文件。型号或颜色无法匹配时保留文字。库存请求仍使用当地货号。

相同外观可能对应不同货号。例如 iPhone 18 Pro 黑色 256GB 在日本是 `MJR54J/A`，台湾是 `MJRP4ZP/A`，香港是 `MJRP4ZA/A`。查询结果要同时匹配地区、当地货号和门店号。库存会变化，实际下单时请以当地 Apple 结算页为准。 [日本商品页](https://www.apple.com/jp/shop/buy-iphone/iphone-18-pro) · [台湾商品页](https://www.apple.com/tw/shop/buy-iphone/iphone-18-pro) · [香港商品页](https://www.apple.com/hk/shop/buy-iphone/iphone-18-pro)

## 用量与提醒

地区目录随服务端代码提供。进入「其他站点」后按需读取，同一页面短时间返回时可复用目录。切换地区、规格、语言和窗口宽度均在本地完成。多位用户关注相同门店和货号时，采集器会合并请求。只有有效会员已关注的目标进入后台队列。

每站默认上限为每分钟 6 次、每天 7,200 次。采用默认 80% 自动预算时，全天一分钟一组需要 1,440 次，4 组共需 5,760 次。手动查询在该站开启监测时最多使用余下的日预算。目标超出容量时会拉长后台检查间隔。错误、限流、轮询进度分别按地区保存。真实确认和微信投递均受数据时效、授权、额度和服务可用性影响。

首次发现有货只建立基线。直接观测到不可自提转为可自提，还需第二次有效样本确认。若常规检查间隔已经拉长，在该站预算和告警有效时间内优先安排一次复核。采集中断后的恢复、尚未开放自提和不支持自提，均不会被当作补货。在发送前再次核对关注、接收账号、授权语言、额度与库存，避免取消后继续提醒或用其他语言代发。

## 本次实际验证

本地自动化测试通过 2,080 项。发布检查通过 65/66 项，剩余一项需要当前包的微信后台质检回执。

已逐项对照三地 96 个当地货号及大陆目录的同款外观。中文版和英文版均使用相同的 8 张现有商品图，商品图片目录新增 0 个文件。切换型号、颜色、容量和站点均纳入回归。离线 Chromium 在 320、375、430、899、900、1200px 六种宽度验收五个查询、关闭或关注场景，浅色和深色共 60 组。 [手机示例](../evidence/design/3.8.0/markets-mobile.png) · [桌面示例](../evidence/design/3.8.0/markets-desktop.png)

微信开发者工具基础库 3.17.3 的 430px 模拟器通过原生编译和交互验收。在隔离工程中，实际解码包内商品图并切换颜色，选台湾台北 101，用测试账户查询、保存关注并切换英文。检验了门店当地时间和 48px 主按钮。

在本地模拟同一补货事件，已验证确认后只投递一次、符合条件的授权额度只扣一次、点击通知只回到接收账号的目标。另以模拟时钟和固定测试响应运行 1,440 个连续分钟，每站各一组，分别取得 1,440 次有效请求。单站限流、其他站点继续采集和三分钟常规检查下的优先复核另有回归。线上实际间隔与真机收信仍待第 3、4 步确认。

## 维护者上线验收

1. 部署候选版 `gxs_api` 和 `gxs_monitor`，下载线上函数包核对实际代码与定时触发器。在两个服务都升级完成前，保持三站能力关闭。现网共享鉴权仍使用已授权两款应用的版本。本版的地区目录内置在业务函数中，无需给大陆目录补录门店。
2. 按数据来源获准的用途和频率逐站开放。管理员编辑器先读 `admin.getConfig`，带返回的 `expectedRevision` 通过 `admin.updateConfig` 更新需要的字段。手动查询用 `internationalMarkets`，后台监测用 `internationalMonitoring`，微信提醒用 `internationalNotifications`，各按 `JP`、`TW`、`HK` 控制。先在体验版逐站对照一次同货号同门店的实际查询，再开启该站监测。检查 `collector.enabled`、`notifications.enabled` 和发送器就绪状态，保留大陆现网配置。
3. 微信后台确认到货模板及字段映射。中文使用 `notifications.templateIds.restock`，英文使用单独的 `restockEn`，与当前到货字段映射一一对应。缺少获准的英文模板时页面会说明。使用体验成员自己的账号在真机授权，查看对应模板是否到账、点击后是否回到对应站点、配置和门店，核对只扣一次。参考[订阅消息配置](SUBSCRIBE_SETUP.md)。
4. 在受控范围跨日连续观测至少 24 小时，分别核对各站的真实请求数、成功观测、实际间隔、限流、预算和最后一次有效时间。验证一站暂停不影响大陆及其余站点，关注取消后没有后续发送。同步复测大陆老用户的原关注、查询和微信提醒。
5. 上传同指纹体验版后，复测此前的四项微信质检，包括未使用组件、原生底栏首切、商品图体积和格式。手机实测原生导航、选择器、语言及提醒回跳。电脑微信拖动窗口核对 899px 与 900px 两侧布局。维护者最后办理提审和发布。

## 回退

单站异常时，先关该站的发送和监测，再按需关手动查询。关站后已扣次的在途查询仍可核对原请求，超时结算按原规则退回。关闭地区开关不会自动释放会员关注名额。

如需退回旧客户端，可保留能识别地区的 3.8 后端，保留客户记录。旧采集器和旧 API 不理解新关注的地区字段，直接降级可能让地区货号进入大陆队列或旧端名单。完整回退前须停住受影响的写入，在备份中核对并隔离地区关注及在途任务，再恢复成对的旧函数和流量。每步完成后复查大陆目标、消费账本和真实提醒。
