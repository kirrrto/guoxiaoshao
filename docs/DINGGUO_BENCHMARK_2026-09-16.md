# DING果实际体验与果小哨改进记录

日期：2026-09-16。用户要求亲自体验主要竞品，并据此提升果小哨。使用当前 Windows 微信中已经打开的 DING果，通过原生界面操作与可访问性文本核对。本文是本轮开发记录，不宣称取得竞品源码、网络协议或后端实现。

## 实际操作了什么

- 从个人中心进入历史页，打开全国榜单；榜单包含最近 1 小时、今日累计、城市记录数量、涉及门店与最近记录时间。
- 点击成都排名，实际跳转到成都、iPhone18 Pro Max、当天的放货记录；看到两家门店以及颜色/容量筛选。
- 打开数据分析，等待更新后核对成都条件：今日概览、24 小时分布、颜色及容量分布、门店排行均可见。切换城市和分析时短暂保留旧内容，随后更新；这不是长期错误的证明。
- 打开数据说明：页面说明手动记录来源于用户实时查询，自动记录来源于后台检测；是否推送还与关注和通知次数有关。这里只记录竞品自己的解释。
- 回到查询页，看到“实时查询”和“添加到货提醒”双入口。实际点击实时查询后，当前免费账号收到新品发售期间限制手动查询的提示；没有得到有效库存结果。
- 进入关注页，看到自动监控中/已结束和机型筛选；当前账号无关注，没有创建新任务。
- 进入个人中心的到货提醒使用指南，实际阅读“准备通知次数→测试通知→添加关注”的引导，及会员有效、次数充足、任务监控中三个检查项。
- 结束时返回竞品个人中心。没有购买会员、补充订阅授权、发送测试通知、联系客服或修改账户权限。

## 体验所得

竞品更成熟的部分在完整流程：榜单能进入城市记录、分析使用城市和整个机型范围、提醒指南将下一步操作放在对应说明旁。不能只增加玻璃样式就认定产品竞争力已经超过它。

各页面“通知次数”在加载前后发生变化，本轮没有调查原因，不把旧快照与加载后数值差异断言为竞品扣错次数。当前账号处于免费状态，本轮没有验证其付费监测质量、真实补货消息送达或全国监测实际覆盖。

## 本轮已落实的改进

1. 修复每日历史浏览任务：会员和免费用户均可完成；成功加载免费浏览摘要即获得当天任务奖励；无需先消耗查询次数。账号的任务、余额与展开的明细同步更新，重复浏览不会重复奖励。
2. 查询页新增直接关注入口：把当前选择的型号、容量、颜色和门店带入关注编辑页，不必先查库存。旧结果卡的关注动作仍使用旧结果自身配置，避免错绑。
3. 修复过期查询快照的主徽标：旧数据改为待更新，过去结果明确标记为参考；可见时只在本地重算有效期，不自动扣查询次数。
4. 修正历史记录的时间解释：采样间隔不再称为“距上次可取货”；近一小时统计显示对应查询快照的截止时间。

## 仍然存在的产品差距

### 整个机型的历史与分析

果小哨当前 `history.list` 按单个 partNumber 查询，即一个容量和颜色。要覆盖竞品的机型级历史，需要服务端支持机型、颜色、容量、城市、门店、日期的组合筛选，并保持新品权限和按次计费一致。小时图、配置分布、门店排行必须针对完整筛选范围统计，不能把第一页 100 条当作全天数据。

### 全国榜单与覆盖透明度

当前自动采集围绕有效会员的已开启关注，不能把已有两家门店的成功样本说成全国完整覆盖。榜单除了记录数，还应展示实际覆盖门店/配置、最近观测和缺失范围；缺记录不能等同于没货。全国目录、全国监测能力和全国历史完整性是不同能力。

### 提醒开通与诊断

果小哨已有会员、关注、后台运行、模板、授权等分层状态。下一步应将通知授权余额、补充授权、明确标为测试的通知和排查指南集中，减少在“我的”和“关注”之间寻找入口。真实模板、发送凭据和手机授权未配置前，不能把测试按钮做成虚假成功。

### 保留用户已确认的目标

全国主要品类、活跃关注秒级检测仍是既有目标；当前部署的是分钟定时任务，不把当前实现改写成最终速度目标。秒级实现还需对常驻运行、上游承载、限流与成本验证。支付继续暂缓，补货提醒的真实配置与验收独立推进。

## 果小哨如何形成优势

应让用户更快回答三个问题：这个配置现在是否值得去看、哪家门店最近更活跃、提醒为什么没有到。对应方向是可靠的时效标签与覆盖说明、真实可比较的机型分析、可操作的提醒诊断和不重复的事件提醒；成果以真实使用和记录验证，不能用功能数量或样式代替。
