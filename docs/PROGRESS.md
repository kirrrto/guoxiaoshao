## 已实现

### 查询、次数和历史

- 查询扣次与 pending 记录在同一事务；结束记录与退款也在同一事务。重复请求不重复扣费，崩溃后原请求可恢复，旧工作进程不能覆盖新结果。
- 相同查询 ID 必须对应相同商品、门店和日期；门店顺序归一化。
- 免费额度日上限、余额上限、同日奖励幂等在事务内执行。
- 三路有界并发访问上游；失败显示未知状态，全部失败返还次数。
- 库存最新状态与事件同事务提交；迟到样本不会将新状态覆盖回旧状态。
- 历史查询有稳定快照分页、全量计数；受限新品的历史响应不会夹带当前库存。

### 会员和关注

- 会员到期后后端拒绝新增/恢复监测；列表清楚显示已到期，保留原设置。
- 3 个具体配置、每配置 3 门店的限制在事务内校验；容量和颜色分别占配置名额。
- 管理员并发重复发放同一会员请求只延期一次；不同订单顺延保留的剩余天数。
- 用户页面清楚区分免费次数、会员不扣次、新品窗口和微信订阅额度。
- 支付购买入口关闭，真实支付集成留待下一轮。

### 采集与微信提醒

- 运行配置真正控制间隔、并发、分片；429/503 熔断和重试间隔不会被旧在途成功响应提前解除。
- 请求量日/分钟预算持久化，重启不清零；状态过期、无租约、限流和停机不会显示为健康监测。
- 手动查询和自动采集发现的事件进入同一持久消息规划流程。
- 通知任务确定性去重、原子领取、发送额度预留；发送前再次验证用户与配置。
- 微信明确拒绝与不确定发送结果分别处理，避免超时后盲目重发。
- 常驻进程包含健康检查、优雅关闭、部署模板和运行手册；本地模拟验证通过，真实服务尚未启用。

### 产品图片和 UI

- 选择器按机型、容量、颜色及剩余配置逐级选择。
- 292 个目录 SKU 已映射到 113 张不同的官方原图；原图已逐张 HTTP 获取和完整解码校验。
- 查询、历史选择器及关注缩略图使用精确 SKU 对应关系，加载失败保持固定占位。小程序附带精确图片索引，以兼容尚未更新图片字段的旧云端目录。
- 修复实际微信编译发现的 WXML 表达式转义错误、属性更新期间回写警告和组件不允许的 WXSS 选择器。
- 公共布局支持换行和伸缩；实际 WXML/WXSS 派生的离线预览覆盖 5 页 × 6 状态 × 3 宽度，视觉和溢出检查记录见验证文档。

### 身份与部署资料

- 空 OPENID、未知来源和 HTTP 请求不再自动取得管理员资格。
- 共享身份只认 SDK 可信字段，禁止混用资源方与消费者身份。
- 真实 SDK 事务适配检查包含对象替换、空值转对象、冲突重试和失败回滚。
- 管理配置校验防止负数扣费、无效并发或错误模板字段；局部修改保留既有同级配置。
- 本轮只读确认 12 个业务集合均为 ADMINONLY；新增索引计划已整理。

## 0.2.0 交付时的外部事项与能力边界

1. **支付**：用户明确暂缓，等待主体认证与备案；当前不能购买会员。
2. **正式运行**：当时需要部署该阶段新版云函数及索引、重新导入目录；云端仍是更早版本。1.0.1 部署结果以上方实际操作记录为准。
3. **自动采集和提醒**：需启用常驻实例、配置模板与凭据后验证，不能把离线测试写成已全天候运行或已送达手机。
4. **未验证的商品**：现有目录中取货能力未通过验证的配置继续明确标记，不伪造库存。Apple Watch 的表壳与表带组合目录不包含在当前 292 个 SKU 内。
5. **统计范围**：历史统计覆盖系统实际观测到的事件；未观测时段不能推断缺货，也不代表全网库存或全国实时榜单。
6. **真机**：不同手机、系统字体设置和正式微信环境仍需预览码验证，本轮保留明确的验证边界。
