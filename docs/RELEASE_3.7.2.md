# 果小哨 v3.7.2 发布说明

**本版可交给维护者上传体验版。正式发布仍需同包微信质检、真机支付与收信，以及隔离云环境的容量验收。** 本版更新了四个原生入口和会员选购，修复了切换账号、清空提醒和并发取微信令牌时的异常。GitHub 同步的是候选源码。审查日期为 2026-11-21。

本次消费端源码指纹为 `sha256:f036f76ce56a81c392081ef5cb32eacd19de1bb233d3e6a101e422ab3bba244b`，供上传后关联微信质检报告。

## 用户可以看到的变化

- 会员卡保留果哨标志，集中显示有效期和可用名额。开通或续费时可对照各套餐的价格、门店数与关注配置数，从常见问题返回后继续选购。
- 小哨将保存关注与微信提醒授权分开说明，开通会员后仍需确认门店并保存。切换账号时，购买页会先核对当前账号的待确认订单。
- 清空提醒记录后，从旧微信服务通知进入，不能再用旧记录暂停关注。

## 本次交付与回退

消费端、`gxs_api`、`gxs_monitor` 均有运行逻辑变更。后端继续支持旧客户端，提醒清空同时识别旧记录的建立时间和新记录的写入序号。本次没有数据库结构迁移，也没有新增采集轮询。请使用锁定依赖部署两项业务云函数并核对实际代码包。共用的 `cloudbase_auth` 在线上服务两款应用，部署时沿用现网共享授权。回退时分别恢复上一次经核验的客户端版本及云函数包，保留用户订单、关注及提醒记录。

## 微信与云端验收

1. 导入含 `project.config.json` 的项目根目录，微信开发者工具上传版本填 3.7.2。在公众平台选定本次上传包，登记包版本、任务号、执行时间及基础库。完成未使用组件、底栏首次切换、商品图体积、图片格式四项质检。[质检登记表](../config/wechat-quality-findings.json)
2. 在 iOS 与 Android 同包冷启动，首次切换四个 tab，检查商品图、深色、大字体、读屏以及套餐页返回。用测试账号新建关注并确认门店，分别在同意和拒绝订阅后核对状态。到「我的 → 通知与免打扰 → 体验微信提醒」用一次查询次数发起测试，打开微信服务通知核对实际收信。
3. 维护者部署后核对两项函数代码、定时任务与自动采样。若开放支付，核对真机支付、付款中断后恢复原单、权益到账及换账号显示。清空测试账号提醒后，旧消息应无法再暂停关注，新提醒仍可打开。
4. 在隔离云环境按实际门店分布验收 300 名同时查询的会员，检查完整结果、限流、尾延迟、自动采样时间和繁忙恢复。目标为普通关注 60 秒、持续有货时 3 秒复查。[容量目标](../config/delivery-targets.json)
