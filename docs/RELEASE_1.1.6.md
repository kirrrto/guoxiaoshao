## 支付确认与恢复

仅在用户明确点击购买时执行微信登录、创建订单和拉起收银台。价格、商品、天数及签名由服务端确定；前端原样传递签名，不自行计算或修改金额。

微信支付窗口返回成功后，页面先进入确认中。服务端核对平台订单和金额、完成权益持久化后，前端才显示会员开通。订单与平台交易号的重复通知不会重复发放权益。

待确认订单按微信账号分开保留。退出重进只恢复查单，不自动付款或创建另一笔订单；前端采用有限轮询，隐藏页面和卸载时停止。平台已经受理但尚未确认付款的订单只能等待查询，不重复拉起收银台。

### 取消支付的已知边界

取消后显示“已取消本次支付，请查询订单状态”，保留订单编号，先提供查单。只有服务端确认可安全恢复，用户才可以主动继续同一笔订单。

**已签发支付参数，但客户端尚未拉起收银台或用户已经取消时，平台查询可能暂时没有可确认的订单结果。** 当前尚未取得可依赖的官方“订单不存在”错误码合同，因此不把未知错误或错误文案解释成“确定未付款”。这类订单可能继续保持待确认，不能承诺取消后立即重新购买，也不会自动更换订单号重试收费。

明确尚未签发过支付参数、未产生平台交易的本地订单，可以在服务端核对后继续原订单。取消、关闭小程序、恢复查单与重新购买的真实平台表现仍须在真机联调中确认。

## 权益账本与退款

会员权益按来源订单记入账本。累计退款只撤销对应订单尚未使用的权益，不扣减另一笔购买或兑换产生的权益。部分退款先于发放时，仅发放确认后的净权益；全额退款后的旧付款通知不会重新开通会员。

退款回调需要经过安全模式验证及权威订单核对。对账尚未反映退款金额时返回重试；同退款 ID 的重放保持幂等，不同退款 ID 不能重复占用同一笔已确认退款金额。

## 回滚注意事项

本版增加按订单来源记录的会员权益账本，涉及购买、兑换、退款及后台读取。**不能直接用只读写 `expiresAt` 的旧版本覆盖当前 API 或监测函数**；旧版按到期时间整体写回，可能丢失或覆盖新版权益账本，进而破坏退款归属和后续续费计算。

- 出现问题先关闭新购买入口；在配置允许的情况下，保留能够正确处理在途付款与退款的兼容回调和查单服务。
- 调整数据或版本前，备份完整会员记录、订单、支付／退款确认记录及相关配置，保留权益来源和幂等记录。
- 优先使用兼容当前权益账本的数据修复或代码回退方案，保持 API 与监测端共享权益逻辑一致。
- 如必须退回旧版，先隔离会写入会员数据的路径，验证数据转换和在途订单补偿方案；不要只手改到期时间、清空权益账本，或直接覆盖新记录。

回滚完成的判断包括数据与在途订单处理结果，不能仅以函数重新进入 `Active` 状态为准。
