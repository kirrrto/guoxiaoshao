## 核心改动与边界

- **商品图片与“修改”按钮**：按精确官方原图、SKU 和哈希生成 119 个包内展示资源（47 个透明 256 色 PNG 与 72 个不透明基线 JPEG，合计 595,221 B），覆盖 297 个 SKU、全部展示面、旧缓存及此前 `.webp` 缓存路径；星光白由 684,465 B 降为 5,284 B。保留原始来源，不猜 CDN 参数，失败不回退大图。查询卡片 `.selection-summary-change` 改为自适应内容宽度并禁止“修改”二字断行。新增目录或图片来源必须同步重建并通过素材预算检查。
- **原生底栏**：移除自定义 tabBar 组件，使用微信原生四页导航；保持弹层、键盘、路由和生命周期保护，并对显示/隐藏的瞬时桥接失败有限重试。已知 `channel-video` 审计问题在原版 SDK 空页面独立重现，微信侧验证仍是外部阻塞项。
- **系列排序与门店快选**：`miniprogram/utils/catalog-order.js` 为同日发布的 `iphone-duo` 设置优先权重，使本地种子目录与云端缓存目录均将 `iPhone Duo` 排在 `iPhone` 分类第一位；`miniprogram/components/target-picker` 在未搜索状态下展示常用城市快选胶囊。
- **提醒与任务领奖**：提醒卡片的两个真实点击入口复用既有补次工具，仅对有效会员已记住允许的模板执行，仍受防重入、账号隔离和待同步队列约束；微信授权及同步结果决定是否实际增加次数。历史浏览仍沿用服务端自动发奖，新按钮用于未完成或余额上限后再次领取，不增加奖励、扣次或每日次数。
- **套餐预选与启动性能**：`restoreCheckoutContext` 依据服务端套餐 `limits` 和价格选择能覆盖需求的最低价可购套餐，保留用户手选和待处理订单。目录种子与图片数据延迟加载，查询页减少重复派生操作计算，但账户恢复后始终重新计算库存时效。
- **云端兼容**：相对 GitHub 基线 `da96096`，云函数业务源码、数据库结构及计费协议未变化，云函数包版本统一为 3.3.1。源码层面沿用 v3.3.0 接口，不构成当前线上部署核验；若线上尚未应用 v3.3.0 的提醒逻辑和年卡 5×5 权益，仍须先按 [3.3.0 上线顺序](RELEASE_3.3.0.md#上线顺序) 对齐后端，再上传本版前端。

## 2026-10-20 发布前审查修复

审查以 GitHub `master` 的 `da96096acad0e3c20a3583190edf05f28cbb05f1` 为基线，保留原有优化，并修复以下可复现问题：

- **慢网络下的库存时效**：119 秒旧的有货观测在账户请求等待 3 秒后已经过期，原优化却跳过首次刷新，仍显示「可取货」至下一轮轮询。现在返回查询页和下拉刷新都及时转为「待更新」，取消可取货高亮，不额外查询或扣次。
- **领奖重复点击和失败恢复**：共用在途领奖请求，显示领取中并禁用按钮；重试成功清除失败提示，错误不再声称用户已完成收费历史查询。切换账号及卸载后的旧响应不能修改新页面。
- **套餐误选**：移除按套餐 ID 猜测容量的逻辑；恢复已有配置不重复占新名额，需求降低时重新选择合适套餐，无法满足需求时不默认推年卡。切换账号清理旧关注缓存，防止旧账号关注数量影响新账号预选。
- **窄屏领奖按钮**：显式覆盖微信非 mini 按钮默认 184px 宽度，保留主题绿实心按钮与至少 44px 的操作高度；离线预览增加余额触顶、领取中、失败三种场景。
