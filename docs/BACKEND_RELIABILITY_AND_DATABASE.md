# 后端可靠性、权限与数据库准备

本页对应 1.0.1 后端实现与数据库操作约定。导出脚本只生成本地清单；云端函数、索引与版本核对结果以 [1.0.1 云端操作记录](../evidence/verification/1.0.1/cloud-deployment.json) 为准。1.0.0 阶段的“未部署”结论属于历史记录，不能替代本版实际状态；支付仍关闭。

## 已实现的事务边界

- 实时/历史查询：请求参数与查询 ID 绑定；首次扣次和 pending 记录同事务提交。并发重试只领取一次执行权，其他请求得到 `query_in_progress`；改变商品、日期或门店必须使用新 ID。
- 异常补偿：失败结果、退次账本及用户余额同事务提交。执行者持有 25 秒租约，崩溃后可以使用同 ID 恢复；旧执行者不能覆盖新结果。用户重新进入时，bootstrap 会清算租约已过期超过 2 分钟的未完成记录，退回次数并标记 `query_expired`，每次最多 20 条。
- Apple 请求：最多 3 个请求并行，上游阶段总预算 14 秒；部署时将云函数超时设为至少 30 秒，保留写库与补偿余量。数据库故障仍可能导致平台强制超时，此时依靠持久 pending 恢复，不能把未完成写入宣称成功。
- 库存：每个门店 × SKU 在同一事务中读取最新样本、计算状态迁移，并写入 latest 与事件。旧样本不覆盖新样本；事件保存失败会回滚状态，重试仍能生成事件。
- 免费次数：每日奖励上限和余额上限都在用户事务内重新检查。领取 `view_history` 必须有本用户在北京时间当日成功完成的历史查询；查询完成和任务凭据同事务保存，发奖事务再次读取查询并检查 `kind=history`、`status=success`、`response.ok=true` 与 `finishedAt`。浏览往日数据可以完成今天的任务，重放昨天已完成的同一查询不能重复算作今天完成。仅上报 taskId、失败或未完成查询均不能得奖；`reward=0` 保持关闭。
- 账户设置：只合并本次提供的设置字段，并在用户事务内提交。独立更新提醒开关与免打扰时段不会互相覆盖。
- 管理配置：`admin.updateConfig` 在事务内重新读取 runtime，执行允许字段的局部合并与校验后写入。事务冲突重试会基于最新配置重新合并，避免公告等无关更新把已经关闭的兑换开关恢复为旧值。
- 关注：3 个 SKU × 每个 SKU 最多 3 家门店在事务内检查。会员到期时原 active 关注返回 `expired`，保留 `savedStatus`，续期后可以继续原设置。
- 会员赠送：订单建立和发放使用原子仓储接口。相同发放 ID、不同天数返回冲突；相同次数变更 ID、不同金额也返回冲突。支付入口继续关闭；保留的支付仓储基础方法没有接入收款。
- 真实会员兑换：活动 `launch_30d_v1` 提供 30 天，按可信账号 `appid:openid` 和活动的确定性订单 ID 限领一次。服务端同事务读取兑换开关、错误计数、用户与既有订单，再续期原 `users.membership` 并写入零金额 `fulfilled` 兑换订单。与管理员发放、后续付费购买使用同一有效期与权益逻辑；并发、换请求 ID、重复请求或到期后重试均不重复领取。
- 提醒：持久事件消费、发送任务领取、授权次数预占与返还、同目标冷却窗口、采集预算均由事务保护。发送结果不确定的任务不自动再次发送。

## 兑换活动与正式账号

正式版、体验版可在「我的 → 会员 → 兑换码开通」输入运营发放的活动码，无需开发验收。服务端忽略首尾空白与大小写，只保留 SHA-256 校验常量；前端不包含正确码，用户输入不写入日志、订单或账户字段。

连续输错 5 次锁定当前账号 15 分钟。失败计数必须成功提交事务后，服务层才返回 `invalid_redemption_code` 或 `redemption_rate_limited`；否则抛错回滚会让计数失效。正常验证后计数重置；锁定尚未结束时正确码也不会绕过限制。

`runtime.memberRedemption.enabled` 默认为 true，管理员可以关闭。正确码、活动 ID 与天数不接受客户端覆盖；关闭不撤销已经领取的会员。成功返回原有会员快照，前端重新 bootstrap 后，查询、关注和到期判断读取同一真实账户。付费入口显示「暂未开放」，兑换不依赖收款，也不自动部署采集或授予微信消息额度。详见 [会员兑换配置与验收](MEMBER_REDEMPTION.md)。

## 账户与启动读取

小程序通过云开发获得可信的微信身份，以 `appid:openid` 建立持久账户。当前功能不依赖额外的 `wx.login` 按钮，也不需要先取得头像昵称才能访问自己的会员、次数、关注和提醒设置。尚未实现头像昵称资料编辑、手机号绑定、账户注销和数据导出；这些是资料与账户管理功能，不应把头像昵称作为身份凭据。

`bootstrap` 每次仍读取当前用户、运行配置、采集状态并检查异常查询退次。目录版本和采集状态合并为一次数据库读取；当日奖励摘要随奖励账本同事务维护，关注数量使用随关注变更同事务维护的索引。正常已有摘要的账户，离线仓储调用计数从 7 次降至 4 次；该计数不代表实测手机端网络延迟。旧用户缺少摘要或日期变化时回退到完整当日账本，缺少关注索引时回退关注集合，因此不会因优化只计算最后一页。

新增字段为 `users.quota.dailyRewardSnapshot`、`users.followIndex` 与 `users.taskEvidence.view_history`，均由服务端维护；不要从客户端写入这些字段或绕过事务直接变更奖励、关注集合。兼容旧版历史完成记录的查询使用 `user_history_finished_id` 复合索引，已加入本地部署清单。

## 历史接口与前端约定

`history.list` 保留原有字段，新增 `cursor` / `limit` 入参。默认每页 100 条，最多 200 条；后续页必须携带首轮相同的 `historyQueryId`、SKU、门店、日期。

返回 `pagination.nextCursor / hasMore / total / snapshotAt`。分页以时间和事件 ID 双字段排序；`summary` 使用全日数据库计数，包含 `lastHourRestocks`。最近一小时统计相对首轮 `snapshotAt` 计算，不随翻页改变，也不只统计当前页。

`latestSnapshotAt` 标识库存读取快照时间；每项 `isStale`、`lastKnownStatus` 区分旧状态与当前未知状态。历史事件允许读取不代表有权读取新品当前库存：受限非会员得到 `latestRestricted: true` 与空 `latest`。

前端统一根据原观测时间和服务端有效性判断主标签。超过 2 分钟的旧观测显示「待更新」，旧库存仅在「上次有效结果」中供参考；未取得有效结果和缺少观测分别说明，不同时显示旧库存为当前状态。后端的观测连续性窗口用于判断事件，不能据此延长前端“最近观测”的展示有效期。模拟关注和历史读取不更新样本时间，避免轮询让模拟库存一直保持新鲜。

## 提醒列表、删除与清空

- `notify.list({limit:20,cursor?})` 返回 `notifications / nextCursor / hasMore / clearBefore`。每页最多 100 条，按 `createdAt`、`_id` 倒序；游标固定首次列表快照，后续插入的提醒在刷新列表后显示。单条隐藏和用户清空水位均在查询时过滤。
- `notify.delete({id})` 只隐藏当前用户拥有的提醒，重复操作幂等。不存在与他人记录统一返回 `notification_not_found`；无效 ID 返回 `invalid_notification_id`。
- `notify.clear({before:clearBefore})` 清空首次列表快照内的全部本人提醒，不限当前页。`clearBefore` 和 `nextCursor` 是绑定用户的服务端签名字符串，前端必须原样传回；不能自行构造时间。被篡改、用途不符、其他用户、未来时间或超出已入库序号的令牌返回 `invalid_clear_before` / `invalid_cursor`。
- 新通知通过事务同时写入任务和用户递增 `viewSequence`，独立元数据保存在 `gxs_config/notification_view_<用户哈希>`。清空事务只单调推进该用户的序号水位；同毫秒入库或携带较早事件时间的新提醒不会被旧清空操作隐藏。旧版无序号记录使用首次列表时间兼容过滤。
- 有序号的现代提醒只按序号范围决定是否属于列表快照；`snapshot.at` 仅限制旧版无序号记录。不能再给现代提醒叠加 `createdAt <= snapshot.at`，否则请求处理期间入库的提醒可能未显示却被清空。分页游标保留创建时间排序，但允许现代提醒的创建时间晚于请求开始时间。
- 删除使用 `userHiddenAt`，清空使用元数据水位，均不物理删除通知，不改变发送状态、额度、订阅授权、去重 ID 或目标冷却。在途任务可正常完成；清空列表不等于取消订阅提醒。
- 发布时 API 与常驻提醒消费者必须使用同一版仓储代码，让后续入库均取得序号。为新旧程序兼容而保留了旧记录读取，但旧版直接插入、未分配序号的消费者不能提供同毫秒/延迟入库保护。新增通知视图索引列入部署清单，实际操作与核对结果见本页开头的云端记录。

## 身份与共享鉴权

只使用 `cloud.getWXContext()` 返回的身份，不接受请求负载提供的身份。跨账号用户必须同时具有 `FROM_APPID` 和 `FROM_OPENID`，不会把资源方 OPENID 拼接到源方 AppID。

没有 OPENID 不代表管理员。仅源链首项属于 `wx_devtools`、`wx_localdebug`、`wx_trigger`，后续项均为 `scf`，并且不存在跨账号用户身份时，才作为平台操作来源处理。空来源、未知来源、HTTP 来源、裸 `scf` 或 `wx_client,scf` 不会获得管理员权限。有 OPENID 的开发者工具用户仍须加入 `adminUserKeys`。

`cloudbase_auth` 只认可 SDK 的 `FROM_APPID`，请求中的 `event.fromAppid` 不能替代身份；两者矛盾时拒绝。官方资源复用示例也从 `getWXContext()` 读取源方 AppID / OPENID，原文证据位于 `evidence/official/wechat-resource-sharing.txt`。参考：[微信资源复用文档](https://developers.weixin.qq.com/miniprogram/dev/wxcloud/guide/resource-sharing/)。

## 数据库权限文件

每个 `gxs_` 集合均使用 `config/database.security-rules.json`：

```json
{ "read": false, "write": false }
```

客户端全部通过 `gxs_api` 获取经鉴权的数据，不能直接读写用户、次数、订单、配置、关注、库存或事件。资源所属环境可能还承载其他小程序：这些规则只应用到导出清单列出的 `gxs_` 集合，不调整其他集合。

使用云开发控制台时：打开目标集合 → 权限设置 → 自定义安全规则 → 粘贴该 JSON → 预览并验证。规则需要在用户授权部署时执行；此处没有修改现网规则。使用具备环境访问权的管理 SDK 执行云函数，不受客户端读写规则限制。

## 索引准备

索引的唯一来源是 `cloudfunctions/gxs_api/lib/collections.js` 中的 `INDEX_PLAN`。运行以下本地命令生成逐集合部署清单：

```powershell
node tools/db/export-plan.mjs
```

输出 `config/database-deployment-plan.json`，包含全部集合的规则和索引方向。按清单在云开发数据库的“索引管理”中创建缺失索引。保留已有索引，不删除或覆盖同环境其他业务的索引；同名但字段不一致时先检查来源，不直接替换。

新增索引覆盖：历史双字段分页、门店筛选、事件类型统计、未规划提醒事件、用户未完成查询清算、提醒任务领取/超时、关注完整读取及按日账本。创建后等索引显示可用，再在测试环境执行带门店/不带门店的历史翻页、账本、关注、bootstrap 与提醒任务查询。缺失索引报错应保留原始错误用于定位，不能静默截断记录。

大集合读取使用显式多页读取和稳定排序；按文档 ID 批量读取会拆成最多 20 个 ID 一组。没有把单次 `limit(1000)` 当作读取全集。

## 实测范围与上线前核对

本地离线测试覆盖并发重复请求、扣次与 pending 同事务失败回滚、事件保存失败补偿、崩溃租约恢复、弃置查询清算、305 条历史分页/全量统计、奖励双上限、关注上限、会员赠送失败与并发，以及身份越权与共享负载伪造。1.0.1 增加会员兑换并发幂等、已有会员顺延、到期重试、5 次错误/15 分钟锁定、跨账号隔离及写入失败回滚；配置回归验证关闭兑换与修改公告并发时均保留各自结果。

仓库锁定 `wx-server-sdk@4.0.2`。测试使用真实 SDK 的数据库封装和事务实现，替换底层 request transport 为本地数据，验证以下兼容性：事务 `doc.get()` 返回对象/空值；`add({data})` 与 `set({data})` 形状；事务返回值；commit 与读操作冲突重试；其他错误回滚。兑换测试验证失败计数持久化、订单唯一及续期回滚；配置测试在提交冲突期间注入另一次关闭操作，确认重试不会重开兑换。测试禁止 SDK 元数据环境探测，不使用云端凭据或调用真实业务接口。

特别处理了 SDK `update()` 会把嵌套对象展开成点号字段的行为：原子仓储对已读文档使用 `set()`，从而安全替换 `response: null` 为结果对象。SDK 会包装读写错误并丢失事务冲突字符串代码；仓储只恢复明确的事务冲突信号，交由 SDK 的有界重试逻辑处理。

安装云函数锁定依赖后运行测试：

```powershell
npm ci --prefix cloudfunctions/gxs_api
npm test
```

如果未安装云函数依赖，真实 SDK 契约用例会明确标记 skipped，不能把该次测试称为已验证真实 SDK。离线契约通过不代表云端 IAM、索引、安全规则、共享资源初始化和真机回执已经验证；这些需要部署到目标测试环境后逐项检查。支付配置和收款验证仍按用户要求暂停。
