# 果小哨 0.2.1 使用体验完善说明

本轮针对型号和容量顺序、城市难查找、首次加载与切页迟缓、账户说明、反馈行错位和管理入口位置进行修正。同时补充无需付款的开发版会员功能验收，便于在支付暂缓期间实际操作并检查功能。

## 1. 型号由新到旧，容量由小到大

此前选择器沿用目录返回顺序，数据库返回和 SKU 编码顺序不一定符合用户选择习惯。容量使用字符串顺序时，也会出现 `1TB、256GB、2TB、512GB` 这样的排列。

现在的行为：

- 商品系列优先按已核对的发布时间和目录提供的发布时间、顺序字段由新到旧排列。
- 同一产品线缺少发布时间时，用明确的代际信息辅助排序；屏幕大小不会被当作新旧代数。
- 同代不同型号保持稳定顺序，目录重复刷新后不随机跳位。
- 容量先将 GB、TB 等单位换算成可比较的数值，再由小到大排列。例如：`256GB → 512GB → 1TB → 2TB`。
- 切换型号、容量或颜色时，仍按具体 SKU 更新对应产品图片，不借用其他配色的图片。

排序用的发布时间与免费用户“新品开售 30 天”限制分开管理。真实新品限制仍需根据实际开售时间配置，不能直接拿排序日期当开售日期。

## 2. 城市与门店可以直接搜索

门店选择区新增搜索框，支持城市名、门店名、省份，以及目录覆盖城市的拼音和首字母。

例如：

- 输入「广州」或 `guangzhou`、`gz`，找到广州门店。
- 输入「天环」，直接找到天环广场。
- 输入「广东」，查看该省的门店。
- 输入城市和门店关键词，可以进一步缩小结果范围。

搜索结果保留城市、门店和已选状态，可跨城市选择，并继续受最多门店数量限制。相同拼音首字母可能匹配多个城市，结果中会显示具体城市供确认。清空搜索后恢复城市浏览。

## 3. 首次进入和切换页面

此前目录与账户信息需要等云请求完成后才进入主要选择流程；多个页面还会重复请求账户、关注及会员记录，较大的目录对象反复通过 `setData` 传到视图层。

现在的行为：

- 工程内附带公开商品和门店目录种子，首次进入先显示可选择内容，云端版本在后台检查更新。
- 有有效本地目录时优先复用；后台更新完成后同步页面，减少反复加载相同目录。
- 账户快照默认复用 30 秒，关注列表默认复用 15 秒，并合并同时发出的相同请求。
- 用户手动下拉刷新或完成相关修改后，可以重新取得最新状态；跨日和会员到期会使相关账户缓存失效。
- 关注页面仅在可见时轮询，离开页面停止轮询。
- “我的”中的会员记录按需展开加载，提醒记录短时复用，避免每次切页同时发起多次云请求。
- 账户连接尚未完成时可以先选择商品和门店，页面提供明确的连接状态和重试入口。

本轮同一商品目录发送给视图层的 `setData` 数据量从 **816,991 字节降低到 269,648 字节，减少约 67%**。完整检索索引保留在逻辑层，视图层只接收显示所需字段。这个比例表示传输数据体积的变化；真实首屏耗时和切页流畅度还受手机、微信版本、网络与云函数冷启动影响，需要结合实际设备检查。

## 4. 用户是否需要注册或登录

小程序已有用户系统，采用微信提供的账号身份进行静默识别。用户进入后，无需另外注册用户名、设置密码或填写手机号。服务端从微信云调用上下文取得当前小程序的 AppID 与 OpenID，并为首次使用的账号建立用户记录。

用户记录承载会员有效期、查询余额与账本、关注、免打扰设置、订阅授权次数和提醒记录。客户端显示的会员和余额由服务端规则控制。

目前不要求用户提供昵称、头像或手机号，也不通过微信头像、手机号授权弹窗完成登录。补货订阅消息属于另一项授权：实际微信提醒需要用户单独同意订阅，不能用账号静默识别替代。

共享云环境中的消费者账号使用对应的 AppID 与 OpenID 配对识别，避免与资源方账号混用。

## 5. 反馈行与管理入口

- 使用说明、隐私说明、免责声明与意见反馈使用一致的行布局。
- 反馈按钮清除原生默认边框、伪元素与对齐干扰，文字靠左，箭头固定在右侧。
- 页脚去掉冗长目录版本时间戳，减少无助于使用的技术信息。
- 普通用户“我的”页面完全移除管理后台入口。
- 独立管理路由在显示内容前，先向服务端实时检查管理权限；权限检查失败时不显示配置、统计或用户数据。
- 每个管理接口继续进行服务端鉴权。隐藏入口只是界面调整，不能代替权限校验；直接构造请求也不能获得管理能力。

原生开发者工具复测还发现微信原生按钮默认样式会覆盖单个 class 的宽度和对齐。现已提高反馈行和通用按钮的样式优先级，重新确认“意见反馈”左右对齐及验收按钮整行宽度，同时恢复按钮之间的上边距。

开发版新增的“功能验收”是独立本地验收工具，不授予管理权限。

## 6. 不开支付，也能实际验收会员功能

入口为开发版的 **「我的 → 功能验收」**。它默认关闭，仅在确认运行版本为 `develop` 时可开启；体验版、正式版和无法确认版本的环境不开放。

可以选择三种身份：

- **普通用户：** 从 0 次余额开始，检查签到、历史体验任务、查询扣次、余额不足及失败退次。
- **有效会员：** 无需付款即可检查查询不扣次、3 个具体配置 × 每配置 3 家门店、暂停、恢复、删除及第 4 个配置被拒绝。
- **会员到期：** 保留关注配置，检查监测和提醒停止，以及新增、恢复关注受限。

应用场景后，操作发生在原有查询、关注、历史与我的页面，包含实际选择、提交、展示和状态变化。验收页还提供示例关注、模拟授权与模拟补货操作，可检查历史事件、免打扰、授权次数和提醒冷却。

验收库存提供暂无供应、可取货、状态未知和接口失败场景；也可开启新品限制检查不同身份的查询权限。

验收数据使用独立本地存储，查询结果、选择条件和待确认请求也与真实模式隔离。验收接口不调用云函数、不修改真实会员、不创建真实支付订单，也不申请或发送真实微信订阅消息。模拟提醒明确显示“验收模拟，未发送微信”。未知验收操作直接拒绝，不回退到真实接口。

「重置验收记录」清理本地验收状态；「退出验收」关闭模式并恢复真实账号与云服务。详细操作步骤见[无付款的会员功能验收](MEMBERSHIP_ACCEPTANCE.md)。

验收与真实业务规则做了交叉检查：开始和结束相同为全天免打扰；历史分页基于固定快照，重试与翻页不重复扣次；未知库存不生成伪变化事件，全未知查询会退次。自查还修复了到期会员从关注列表绕过新品限制的问题，受限新品当前库存及关联时间、报价均由服务端清除，原关注配置保留。

## 7. 当前交付范围与后续联调

本轮完成源码和本地功能验收能力，支付继续按要求暂停。新版云函数尚未部署，真实采集和微信收信仍待配置及联调。

本地验收可以检查实际页面交互、权限分支和状态呈现。真实链路验收仍需部署对应云函数、准备数据库索引、接入常驻采集与订阅模板，并在手机上验证真实账号、网络延迟和消息接收。模拟库存、模拟会员及模拟提醒不作为真实采集运行或微信送达的证明。
