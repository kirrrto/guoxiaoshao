# 果小哨 v1.4.1 发布说明

日期：2026-09-28。基于正式 v1.4.0 和 `57185d6` 的稳定性修复，版本号统一为 **v1.4.1**。本版修复操作和监测边界，不改变 7 元／7 天会员商品、身份来源及支付权益规则。

## 最终评审与修复

### 后台监测与通知

- 平台剩余时间工具抛错时采用有界回退，避免监测启动即失败；沿用当天已确认恢复的修复。
- unknown 观测中断连续确认，恢复后需要再次确认，不将一次恢复样本直接当作可靠新补货。
- 区分已确认状态和短暂跳变，防止未经确认的短暂有货引出断货提醒，或短暂断货恢复后重复补货提醒。
- 刷新目标保留正在进行的快速复查；旧事件重读沿用原事件时间，不延长 20 秒静默退出。
- 同门店多批型号共享请求间隔，目标变更和冷启动不会绕过限速；旧版观测记录在升级时保留已经确认的库存阶段，避免漏掉真实断货。
- 上游、令牌和消息请求使用执行期限与实际租约剩余时间的较小值，预留 1 秒持久化余量；扣额事务后再次检查时限和租约。未开始发送时退回额度并重排队；已开始发送但结果不确定时不盲目重发。

### 查询、关注与提醒界面

- 查询、历史查询和转关注在点击时读取选择器最新状态，避免快速切换后提交旧配置。
- 关注保存成功与后续刷新失败分开显示，旧列表不得覆盖刚保存的关注；云连接初始化竞争和目录失败重试已有修复。
- 新提醒次数使旧账户请求失效，自动补次数与手动授权共享执行锁；待同步记录按请求 ID 清理，网络不确定时保留原 ID。
- “买到了”等反馈只修改原提醒卡片，关闭、切换或卸载后不被迟到响应改写；服务端已暂停关注的结果仍保留。

### 支付、权限与发布材料

- 修复支付 HTTP 回调非法百分号编码逃逸错误边界，畸形请求稳定返回 403；认证、查单和权益发放保持原规则。
- 本次支付／权限评审未复现越权、虚假支付确认或重复开通会员；这不是无漏洞保证。
- README 改为当前版本入口，旧功能说明保留于历史文档。新增根锁文件、README 和发布说明版本一致性门禁。

## 微信前端发布前的真机抽测

1. iOS、Android 冷启动及失败重试；快速切换型号／门店后立即查询、查看历史、保存，核对实际目标。
2. 关注保存后读取超时仍保留已确认关注，返回页面可刷新后台状态。
3. 授权次数增加时反复切页、刷新；同时点查询和授权，核对本地和服务端最终次数。
4. 从真实提醒进入，反馈“买到了”后立刻关闭或打开另一条提醒，确认旧响应不影响新卡片，关注确已暂停。
5. 真实事件分别验收到货和断货模板送达；平台接受不等于手机收到。
6. 既有手机购买成功事实保留；v1.4.1 的 iOS／Android 付款、开通、续费和退款仍需分别记录真实订单验收。

打开率是否改善，需要发布后同口径、足够样本的微信统计验证，源码检查不能证明指标已上升。
