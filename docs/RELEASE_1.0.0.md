# 果小哨 1.0.0 首版发布准备

更新：2026-09-15。本文件对应已整理的首版候选源码，尚未提交微信审核或正式发布。真实支付继续关闭。代码检查通过与微信账号具备发布资格、云服务已部署是不同的验收项。

## 首版功能

- 按系列、机型、容量、颜色及门店查询取货信息；系列新品优先，容量数值升序，图片按 SKU 对应。
- 城市、门店、省份、城市拼音及首字母搜索，跨城选择保留已选门店。
- 微信 OpenID 静默账号，签到、历史体验任务、查询扣次与失败退次。
- 会员不扣查询次数；3 个具体配置 × 每配置最多 3 门店，暂停、恢复、删除和到期限制。
- 历史分页、库存未知/中断标记、免打扰和订阅消息额度。
- 「我的 → 提醒记录」支持单条删除、清空和加载更早提醒，取消确认不执行操作，失败可重试。
- 开发版「功能验收」可无需付款验证普通、会员与到期状态；正式版、体验版不可启用。

## 提醒记录验收步骤

1. 在开发版「我的 → 功能验收」应用有效会员，建立示例关注，模拟授权与补货。
2. 返回「我的 → 提醒记录」，检查商品、状态、时间与删除按钮排版。
3. 点击「删除记录」后先取消：记录保留。再次确认后该条从本人列表移除，较早记录可补位。
4. 点击「清空」：确认后清理本次列表快照内的全部本人提醒，包含未加载的页面。新到提醒继续保留。
5. 生成新的模拟补货，确认新记录可以出现；清空不取消关注、不删除库存历史，也不重置提醒冷却或授权次数。
6. 真实环境部署后，用两个测试账号复核归属隔离、20 条以上分页、删除持久化、全部页面清空、超时后重试以及确认期间新提醒保留。

删除仅清理个人展示列表，内部发送任务保留以维持发送去重、冷却和在途处理。它不撤回已经发送到微信的消息。

## 本轮自查修复

- 提醒清空采用服务端签名的快照令牌和每用户递增序号，避免同毫秒和延迟入库的新记录被误清。
- 清空水位事务单调推进；单条删除校验归属并支持幂等重试。界面拒绝旧的刷新/分页响应复活已删除记录。
- 额外复核列表请求与入库并发、打开确认框期间旧分页返回，以及清空成功后刷新失败；现代提醒按同一个序号范围读取与清理，个人卡片使用中文状态和异常说明。
- 旧订阅模板被明确拒绝后清除失效待上报记录，允许重新授权；网络结果不确定时继续保留原请求编号。
- 停止读取和新存储未使用的 UnionID，保持账号用途与 OpenID 隐私说明一致。未清理生产历史数据。
- 两份云函数锁定 wx-server-sdk 4.0.2，并提供依赖锁文件；业务版本探针由包版本派生，统一为 1.0.0。
- 管理页面和开发验收页面禁止搜索收录；真实支付仍固定关闭。
