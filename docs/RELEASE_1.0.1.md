# 果小哨 1.0.1：会员兑换与库存状态修正

**发布清理更新：** 功能验收页面、入口和模拟运行时现已从小程序上传目录移除，所有版本直接使用真实微信账号。当前发布请看 [1.0.1 发布清理版](RELEASE_1.0.1_CLEANUP.md)。本文下方模拟退出步骤及原生记录描述的是清理前的 1.0.1 首次打包，不再作为当前操作步骤。

更新：2026-09-15。本版承接 1.0.0 首版候选，增加正式账号兑换会员的入口，保留后期付费购买方式；本轮继续关闭收款。发布、云端部署与真实设备验证的结果分别记录，源码版本不代表已经通过微信审核。

## 两种会员开通方式

- **兑换码开通**：在「我的 → 会员 → 兑换码开通」输入运营方提供的兑换码，服务端验证后增加会员有效期。体验版与正式版均可使用，无需开启开发验收。
- **付费购买**：入口保留为「暂未开放」，后续完成主体、备案、支付配置及支付回调后再接通。兑换与付费会员使用同一份账号有效期和权限规则；不是两套会员。

本次兑换活动提供 30 天会员，每个可信微信账号限领取一次；已有有效会员从当前到期时间继续顺延，到期账号从本次兑换时间开始。重复点击、响应超时重试与换请求 ID 都不会多领。兑换码只在服务端校验，前端不存正确答案，也不能提交会员天数或到期时间来授予权限。

用户指定的活动码及服务器配置见 [兑换配置](MEMBER_REDEMPTION.md)。管理员可以停止兑换活动，已生效会员按原有效期保留。

### 当前处于模拟验收时

先使用会员卡里的「退出模拟并兑换」切换回真实微信账号，再输入兑换码。本地验收记录保留，兑换不会发送到本地模拟接口，也不会把模拟会员搬入真实账号。

## 库存状态修正

此前前端超过 2 分钟提示过期，但后端的 5 分钟连续观测窗口仍保留旧库存，导致同一行同时出现「暂无供应」和「观测已过期」。本版统一主状态与有效性展示：

- 旧观测：主标签「待更新」，旧值单列「上次有效结果」，不再当当前库存。
- 缺少观测：「等待首次观测」。
- 未取得有效库存：「状态待确认」，遵守服务端的 `isStale` / `unknownSince`。
- 零时长不再写「持续 0 秒」；非零时长说明为「距本轮首次记录」，不声称中断期间持续有观测。
- 关注页、查询页关注摘要与历史页最近观测使用同一展示函数。返回页面或网络刷新失败时也按原记录时间判断，不伪造更新时间。

模拟验收只有主动查询或「模拟一次补货」才生成新观测；每 15 秒读取关注列表不生成新样本。真实会员授权与持续采集服务是两项能力：兑换会员不会自动部署采集进程，也不会自动获得微信消息授权。

本轮全量 222 项回归通过，155 个源码文件检查无错误，13 项本地发布预检通过，150 个离线布局场景无检测到的溢出、缺字或裁切。原生开发者工具已验证退出模拟、真实账号加载和兑换输入；最终领取未代用户提交。详细范围见 [验证记录](VERIFICATION.md)。

两份云函数已更新为 1.0.1 并回读验证，新增 16 个缺失索引；下载后的代码与本地源文件逐一相符。备份、版本探针与权限检查见 [云端记录](../evidence/verification/1.0.1/cloud-deployment.json) 及 [代码校验](../evidence/verification/1.0.1/cloud-code-integrity.json)。这不是微信小程序提审或发布操作。

本地安装云函数依赖后运行 `npm test`、`npm run check` 和 `node tools/release/check.mjs`。本轮验证日志保存在 `evidence/verification/1.0.1/`，视觉预览使用 `--stock-only` 覆盖不同观测状态，会员兑换的空输入、错误、处理中与成功状态也应检查窄屏布局。

云端更新应保留原函数备份，仅更新本项目 `gxs_api` 与共享鉴权 `cloudbase_auth`，按已有计划添加缺失的 `gxs_` 索引，保留现有索引和其他业务数据。部署后检查版本探针为 `1.0.1`、可信用户身份要求、支付关闭及正式账号兑换路径。

微信上传和提审还需主体、备案、类目及隐私配置满足当前平台条件，并用 iOS/Android 检查输入键盘、安全区、长文字、失败重试与实际网络。自动采集和订阅提醒若未部署，页面应继续如实显示等待启动，不能把会员已开通等同于正在采集。
