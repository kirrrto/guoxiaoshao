## 版本更新

根 package.json、根锁文件、三个云函数的包和锁文件、前端 config/version.js、README 与对应 RELEASE_<版本>.md 使用同一版本。服务端 system.ping 从包版本读取。发布检查拒绝这些文件的版本漂移。

1. 安装根目录和三个云函数的锁定依赖。
2. 后端共享代码修改后执行 `node tools/build-monitor.mjs`，不直接改生成文件。
3. 执行 `node tools/build-monitor.mjs --check`、`npm test`、`npm run check`、`node tools/release/check.mjs`。
4. 按修复分组提交，推送并核对远端 commit 和对应 Actions 结果。
5. 云端更新前保存代码归档、运行时、触发器和配置键清单；更新后下载核对源码，验证真实定时调用。
6. 上传消费者前端并完成真机验收，再按微信流程审核、发布。源码标签不证明真机验收或前端发布已完成。

下载三个云函数到同一个目录后，可执行 `node tools/release/verify-deployment.mjs --download-dir <目录> --out <报告.json>`。该只读检查比对实际 JS/JSON 内容及包元数据，识别同版本旧代码、遗漏函数和额外旧运行文件；云控制面 config.json、云安装可能改写的 lock 文件及 node_modules 不参与哈希。运行配置、触发器、实际安装依赖与业务结果仍须单独核实。不能把源代码检查报告的 `passed=true` 当作 `publicationReady=true`。

## 回退

先保存当前工作和云函数归档，在隔离目录检出目标提交，不用 git reset --hard 覆盖未提交工作。代码回退不会自动回退数据库、会员订单或已发消息。

- 1.1.6 起已有按来源订单记录的权益账本。存在在途支付或新账本后，不可用只写 expiresAt 的旧版覆盖，见 [支付回退说明](RELEASE_1.1.6.md#回滚注意事项)。
- v1.4.1 库存确认状态新增兼容字段，旧记录可继续读取，无需批量改写用户数据。回退旧算法会重新带回中断确认和短暂抖动问题，应优先向前修复。
- 消息已经开始发送而结果不确定时，不可清空状态或手动返还次数来强行重试，避免重复发送。
- 只更新本项目的三项函数，不删除共享环境中的其他函数、索引、数据或触发器。
