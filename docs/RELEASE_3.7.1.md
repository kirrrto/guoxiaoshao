# 果小哨 v3.7.1 发布说明

2026-11-20 整理的补丁版本，包含 3.7.0 开发包上传后的修复。微信上传、提审、发布与业务云函数部署由维护者手动操作。

本次消费端源码指纹为 `sha256:79999056b37e11ffc5858470652f7159d5299a9fea7d1a5b64138020164fa4f4`，供上传后关联微信质检报告。

## 用户更新

- 查询异常时，点「刷新状态」只读取状态。「重新查询」才发起新的库存查询。小哨页分别显示本次检查与上次有效库存的时间。
- 同名到期事项按各自的记录授权。切换账号或离开页面后，原来的删除确认框会失效。
- 周卡和月卡使用绿灰卡面，年卡使用暖金点缀，均保留会员果哨标志。窄屏上的提醒按钮更容易点击，取货攻略切换阶段时能看到对应步骤。

## 维护者发布步骤

1. 用本版锁定依赖部署 `gxs_api` 和 `gxs_monitor`，回读运行包并核对自然定时触发。提醒发送新增对异常回执的处理；线上共享鉴权继续沿用果小哨和「撞词儿」现有授权。
2. 在微信开发者工具导入仓库根目录，上传消费端时填写 **3.7.1**。在公众平台选中这次上传的体验版，核对「我的 → 更新公告」第一条为 3.7.1。
3. 对该包运行微信云测，取得未使用组件、底栏首次切换、商品图大小与格式四项结果，用任务号、设备、基础库和报告更新[质检登记表](../config/wechat-quality-findings.json)。同一体验版用 iOS 和 Android 检查冷启动切页、商品图、弱网恢复和微信服务通知实际收信。若开放购买，核对真实支付和权益到账。
4. 后端的 300 人并发及采样时效仍需在隔离环境验收。11 月 19–20 日审查时，按每分钟 600 次预算模拟 300 人同时查询 900 个不同目标，其中 172 人获得完整结果，1 人获得部分结果，127 人没有取得结果。容量目标见[验收配置](../config/delivery-targets.json)。

升版前的功能与界面验证见[代码审查记录](../evidence/verification/3.7.0/code-review-20261119.md)。本次沿用现有数据库结构。需要回退时使用此前保存并核验的客户端及业务云函数包。
