# 手动查询与自动监测的共享保护

更新：2026-10-01。下文描述当前源码；本次未读取实际云端 runtime、未部署，不能据此判断线上已修复。容量设计与上线核对见 [查询容量](QUERY_CAPACITY.md)。

## 当前请求规则

- 手动查询和自动监测在实际发起取货请求前，共用容量保护。`collector.budgetMode` 默认 `continuous`：`maxRequestsPerDay=10000` 表示持续补充请求容量的速率（10000/86400 次/秒），不是每天用完后停到午夜的硬限额。共享突发容量不超过 `maxRequestsPerMinute=60`，同时保留每自然分钟 60 次的上限。
- 连续容量保存在 `gxs_config/upstream_capacity`，跨北京时间午夜与云函数冷启动保留。`collector_budget_<北京时间日期>` 继续记录 `dayCount`、`minuteCount`、`autoCount`、`manualCount`，连续模式下每日计数用于核对消耗，不决定当天是否停服。
- 自动与手动的持续补充速率分别占 80% / 20%。另一来源至少 60 秒没有需求时，可以借用其空闲容量，但至少保留 1 次供其恢复使用；共享容量和分钟上限仍约束合计请求。容量暂缺返回内部原因 `capacity_wait` 与预计重试时间，不返回次日午夜恢复。
- 如明确需要按北京时间日硬封顶，可配置 `budgetMode: 'daily'`。该兼容模式仍会在日上限耗尽后等到次日，自动监测在总消耗达到日上限的 80% 后停止使用剩余容量。它不适合承诺全天持续查询的场景。
- 一次门店批量请求计 1 次，覆盖其中所有 SKU；自动监测每组默认最多 20 SKU，并按不同门店和 SKU 去重。容量约束针对独立请求组，不是人数，也不是每位会员分别有 10000 次。
- 配额在事务中预留。预留后进程终止、探测过期或失去采集租约时，为防重放超额不返还上游预算；因此统计可能保守高于实际网络请求。采集健康记录的 `requests` 仅统计确已发起并完成的请求。
- `query.maxRequestsPerUserMinute` 缺省为 6，按过去 60 秒的新实时查询计算；`query.maxConcurrentPerUser` 缺省为 1。会员实时查询不扣使用次数，但仍遵守这些服务保护。历史查询不占用取货接口预算。
- 相同查询 ID 的结果重放不重复扣次、不重复发起网络请求，也不重复计入账号请求窗口。不同 ID 也不能绕过同账号并发保护。任务中断后可在租约到期后恢复，旧执行者不能释放新执行者的锁。
- 不同用户查询同一门店与 SKU 时，`query.sharedFreshnessSeconds` 默认 10 秒（允许 0–30，0 关闭复用），可复用近期有效观测，包括自动监测的有效观测。分布式目标租约防止多个手动查询实例重复刷新；等待中的查询短时检查共享结果，仍未完成时返回 `query_refresh_pending`。它不把等待伪装成无货，不自动无限重试。
- 复用保留原 `observedAt`，不增加样本数、不产生重复状态事件或虚假复查确认。全部结果都复用时 `allShared=true`；部分结果复用、其他门店失败且没有新的有效结果时同样不扣次，返回 `billingReason: 'shared_result_no_charge'` 并返还预扣次数。只有至少取得一个新的有效结果才按原整次查询规则扣次。会员不扣使用次数，但仍遵守真实采集容量与账号防刷保护。

## 暂停与恢复

`gxs_config/upstream_breaker` 保存 API 与监测共用的暂停状态。429、503 立即暂停，支持秒数和 HTTP 日期两种 `Retry-After`；其他失败在一分钟内累计五次暂停。默认冷却 30 秒，重复失败指数延长至 30 分钟，服务器要求更长的有效等待时间时取更长值。

冷却结束只允许一个持有 30 秒租约的探测请求。探测失败继续冷却，成功后恢复；旧请求、已过期探测或被接管探测的成功结果不能解除新的暂停状态。数据源请求仍不自动重试、不跟随重定向。

容量拒绝、刷新等待和主动暂停不是数据源观测，不写入最新状态和事件历史，更不会被记成“无货”。没有取得新的有效结果时返还本次使用次数；部分门店取得新的有效结果时保留既有按次收费规则，并说明其他门店暂未成功。页面显示采集时间及预计可重试时间，不展示工程预算或承诺等待后必定成功。

## 数据源边界

当前适配器访问网站取货状态接口，该接口并非本项目取得授权的开放 API。2026-09-16 复核的 [Apple 网站使用条款](https://www.apple.com.cn/legal/internet-services/terms/site.html) 对自动访问、获取、监控网站内容和不合理负载有明确限制。现有代码、低频请求和有效响应均不构成授权或长期可用性保证。

发布及扩大监测规模前，需确认适用授权与数据使用条件，或改接获得许可的数据源。这里的工程保护不能替代该确认。项目没有加入代理轮换、身份伪装、验证码绕过等措施。可取货状态也不代表真实库存数量或门店内部补货时间。

定时触发器仍可每分钟运行，具体目标刷新间隔由去重后的请求组数与容量计算；触发频率不等于每个目标都每分钟得到新样本。消息发送与支付的实际开关应以线上 runtime 为准，本次容量变更不修改这些开关。真实订阅消息需完成模板、服务端凭据和用户授权验证。
