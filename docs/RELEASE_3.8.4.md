# 果小哨 v3.8.4 发布说明

每日签到增加 1 次查询，最多累计 10 次。自动库存检查只覆盖仍有有效关注的配置和门店。有效月卡和年卡可在「其他站点」直接保存日本、台湾或香港的门店，站点暂停监测时会显示实际状态。正式提供到货提醒还需部署本版、逐站开启监测和发送、核对线上自动观测，并在微信真机完成授权与收信复测。

本次消费端源码指纹为 `sha256:e6db7116bf1289a6ccdc69557240ab4191506b252cfd1d84c10ead98ad5c7959`，供上传后关联微信质检报告。

## 客户体验

- 「我的」保留可用查询次数、签到按钮和 10 次上限，移除「今日已获」。按北京时间每天可签到一次。余额已满时可先用掉一次，再于当天签到。新浏览和新历史查询都不会产生奖励。旧版已赚到且当天仍有效的奖励可领一次，既有余额和查询退款完整保留。
- 空关注列表及全部暂停的列表停止定时读取库存。用户主动点击查询仍可检查未关注的商品。后台在发出自动请求前核对每个商品和门店是否还有有效关注，多个账号关注同一目标可共用一次采样。如果在一次请求通过资格核对后取消关注，该次请求仍可能完成。
- 选择支持关注的商品和门店即可保存，无需先查库存。月卡最多保存 4 个配置、每个配置最多 4 家门店，年卡为 5 个配置、每个最多 5 家。大陆及其他站点共用配置名额。周卡保留原有新品查询资格。
- 在套餐选择时可以看到各档支持的站点。关注列表显示保存、暂停或监测状态，用户可以恢复或取消自己的关注。发送微信提醒还取决于站点服务和用户授权。
- 中英文「更新公告」只展示公众客户可感知的改动。之前仅涉及内部试用的 3.8.2、3.8.3 从公告移除，对应维护文档与实际版本记录保留。

## 实测

- 11 月 24 日用普通月卡测试身份，在本地执行新版页面和云函数。公开查询、监测和发送均关闭时，台北信義 A13 的 `MJY04ZP/A` 可以保存、暂停、恢复，刷新后仍可见。全程无需先查库存。
- 相同测试库中，仅开启台湾站监测后，定时任务于北京时间 00:01 从苹果取得 HTTP 200，写入来源为自动采集的「暂不可自提」。暂停监测时上游请求为零。测试未发送真实微信消息。月卡与年卡在三个站点的保存均有回归覆盖。
- 大陆和台湾均覆盖了同批次只取消一个货号、最后一人暂停、其他会员继续关注、资格读取失败。后三种状态分别验证了跳过请求、共享采样及出错停采。未获有效关注确认时不占用剩余采集额度，也不占用苹果接口故障后的首次试探请求。
- 签到覆盖并发重复点击、北京时间跨零点、切换账号、余额已满后使用再领取、旧奖励和查询退款。提醒卡断网恢复可单独确认身份，空关注页无需为此重读库存。
- 已离线检查中英文套餐在 320、375、768、1024px 下的价格、名额和站点名称。320px 英文站点名可换为两行。关注页在 320 和 375px 浅深色下检查了保存、暂停和恢复，关注按钮高 48px、暂停或恢复按钮高 44px。开发者工具自带编译器通过了消费端和运营端的模板、样式编译。
- 更新公告的 18 个场景和签到、旧奖励的 42 个场景分别以浅色和深色复测，共 120 次离线布局检查，未发现文案缺失、横向溢出或裁切。
- 最终源码全量测试 2,176 项通过，无跳过。源码检查、英文资源同步、59 个监测函数共享文件一致性校验通过。本地发布检查 65/66，剩余一项为微信后台针对本版的质检复测记录。

## 部署与回退

1. 部署本版 `gxs_api` 和 `gxs_monitor`，使用匹配的消费端。线上 API 回读为 3.8.3，下载的监测函数包版本为 3.8.2，与本版在准入和事务等源码上仍有差异。部署后核对函数包、每分钟定时触发器与运行状态。客户端读取服务端是否支持提前保存，旧 API 继续按其实际可用能力显示入口。
2. 本轮只读核对时，三个站点的公开查询、监测和发送均关闭，全局采集和发送已开启。要提供自动提醒，在独立运营工具的「运行配置」按站点启用 `internationalMonitoring`，观察该站的自动采样，再启用 `internationalNotifications`。核对该语言到货模板、发送器和用户订阅授权。`internationalMarkets` 单独控制普通用户手动查询。
3. 微信体验版以真实账号检查保存、恢复、取消、监测时间，以及到货通知收信和回跳。微信后台按本版指纹复测四项旧发现（闲置组件、首次切换 tab、商品图片大小、商品图片格式），再由维护者提审和发布。
4. 本版沿用已有关注记录、共享名额、查询账本和采集预算，无需迁移数据。每批次准入会额外核对有效关注和账号资格，定时器也会读云端关注及配置。空列表、关注核对失败或所有目标都已退出时跳过苹果接口。可逐站关闭监测或提醒，已保存记录保留。
5. 若须回退，先关掉受影响站点的采集，再配套回退函数和消费端。旧监测版本缺少发起请求前的关注复核，旧 API 会恢复浏览奖励和关闭站点的保存限制。已入账的签到或退款无需回滚。
