# 1.1.1：每日任务到账与查询体验修复

日期：2026-09-16。版本：1.1.1。原工程直接更新，云函数已部署；消费者小程序尚未上传、提审或发布。

## 每日浏览历史为什么不完成

旧“去完成”只切换页面，服务端奖励证明依赖成功的库存历史查询。页面文案说浏览即可，实际却要执行查询；会员又被前端任务判断排除。即使发生奖励，缓存和已展开的明细也可能未刷新。

本版新增免费 `history.browse`，只返回本人最近浏览的型号、日期、门店条件，不返回受限库存事件。成功读取后记录服务端完成证明，再通过事务发放每天一次的任务奖励；空历史、会员和零次数用户均可完成。库存历史查询仍保留原计费和新品限制，浏览奖励不需要先扣次。

奖励达到每日或余额上限时明确显示已浏览及上限原因，不生成虚假 +1。读取失败提供重试；重复点击、并发请求、跨日完成与请求迟到不会重复奖励。额度增加版本号，避免旧请求覆盖刚发生的扣次、退款或任务状态。返回「我的」后余额、任务标签、已展开明细同步更新。

## 同步改善的操作

- 查询页新增“关注此配置 · 到货提醒”，将当前型号、颜色、容量和门店直接带入关注编辑；不需要先发起库存查询。旧结果卡继续绑定自身结果，避免改了选择后关注错商品。
- 过期查询结果主状态显示“待更新”；上次有效结果和时间单独说明。可见时按本地时钟重算，不自动扣次数或发起上游查询。
- 历史中“距上次可取货”修正为“距上次有效检测”，近一小时统计显示查询快照截止时间。
- 微信连接中断的原始 `empty poll result` 报错转为可理解的中文，保留原请求恢复机制，不把传输失败误判为服务端未执行。
- 已有可用次数时不再提示必须先签到。
