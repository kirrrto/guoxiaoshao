# 果小哨 1.1.2：查询操作、提醒体检与历史准确性

日期：2026-09-16。此版本完善日常查询和提醒操作，修正历史统计口径。原工程继续使用 `C:\Users\Administrator\WeChatProjects\miniprogram-6`。

## 查询更直接

- 已有有效选择时，以商品图片、具体配置、城市和门店组成摘要卡，查询与关注按钮直接可见。点击“修改”展开完整选择器，完成后可收起。
- 修改型号时尽量保留仍可用的容量和颜色；配置不再可选时明确提示调整结果。已经移除或不可关注的原配置不会被静默替换成目录中的第一款商品。
- 查询结果继续绑定发起时的商品和门店。当前选择已经改变时，结果卡明确提示“与当前选择不同”，防止把旧结果当成新条件的结果。
- 查询成功后定位结果区域；异步响应返回时会核对页面可见状态与路由，避免切换页面后发生意外滚动。

## 提醒不再只显示一个总开关

- 小哨页新增“我的提醒体检”，依次检查会员、已开启关注、模板、后台检测、发送服务、用户开关、免打扰和微信授权。
- 每种未就绪状态给出具体原因与可执行入口，例如添加关注、查看并开启关注、查看会员、打开提醒设置、同步授权或查看服务详情。
- 单独显示当前用户已开启的配置数、涉及的不同门店数和补货模板剩余授权。服务整体运行不代表当前用户一定满足发送条件。
- 授权计数只使用实际补货模板；其他模板的额度不会被误算成补货提醒额度。
- “我的”提醒记录根据失败或跳过原因提供对应处理入口。发送结果不确定时先解释并引导检查微信，避免自动重复发送旧消息。
- 免打扰说明明确：期间继续检测，不发送提醒，也不会在结束后补发旧消息。订阅消息的声音遵循微信与手机设置。

## 历史口径和操作修正

- 近一小时确认补货数按完整时间范围统计。北京时间凌晨查询时包含前一天的相应记录，页面提示“含前一日”；日累计仍只统计所选日期。
- 翻页保持同一查询截止时间和原有 SKU、门店范围，不重复扣次。查询昨天及更早记录不会通过近一小时统计泄露受限新品当天的活动信息。
- 检测中断后的事件不再写“本轮可取货持续”。改为记录跨度，并明确“期间检测中断，不能确认连续可取货”；旧记录缺少连续性字段时提示“连续性未确认”。
- 最近浏览增加“恢复条件”。点击只恢复原 SKU、日期和门店，不自动查询、不扣次。用户核对并点击“查看历史”后，才按现有账户规则执行查询。
- 原 SKU 下线、门店已移除或日期异常时整次拒绝恢复并解释原因；不会静默换商品或把失效门店清空后扩大查询范围。
- 不选门店的范围说明改为“各地门店的已有观测记录”，明确不代表全国所有门店持续监测。四类统计下补充其他状态变化与事件总数之间的口径说明。

## 视觉与兼容性

继续使用明亮绿色、扁平口哨标识和悬浮玻璃导航。底栏中央保持清晰，只在两端使用渐进模糊；支持不足时使用基础渐变效果。按钮、底部安全距离、长标题和放大字体均有专项布局检查。浏览器离线渲染用于发现排版问题，最终外观仍需以手机微信为准。

## 仍需配置与后续差距

- **真实微信提醒**：需要在公众平台配置实际可用的补货订阅模板、相应字段和发送凭据，并取得用户主动授权；随后独立验证真实变化、发送记录和手机收信。按 [订阅消息配置指引](SUBSCRIBE_SETUP.md) 完成配置。提醒体检已就绪不等于已证明每条消息能在手机上送达。
- **会员与支付**：兑换入口和会员权益保留；付费购买继续按用户要求暂停。此版本没有重新开启支付流程。
- **数据分析差距**：小时分布、同机型跨颜色容量分析、城市排行仍需后续实现与查询成本评估。统计必须基于完整匹配数据，不能把第一页画成全天结果。
- **采集边界**：现有事件来自有效会员关注的自动检测和用户手动查询。各地已有记录可以做记录分布，不代表全国全量覆盖、库存数量、长期无间断检测或秒级服务能力。

前端体验变化需要使用本版前端代码。仅更新云函数不会改变手机中旧版本的页面。
