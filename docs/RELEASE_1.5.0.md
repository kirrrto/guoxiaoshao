## 用户可见变化

- 查询、小哨和历史复用底部配置面板；页面保留简洁条件摘要，编辑草稿确认后才保存。
- 展开、收起、详情和设置入口使用统一的轻量按钮或整行控件，明确可点击区域和方向，保持与主按钮的层级差异。
- 查询结果改为左侧商品缩略图、右侧名称与快照信息，减少大图容器中突兀的空白。
- 配置摘要的修改按钮移到门店行；已核验的手机图片补偿素材透明边距，完整机身约占图框高度的 92%。
- 查询规则栏与主要按钮左右对齐；展开微信提醒服务详情后平滑滚到内容，收起不滚动，离开页面后取消待执行滚动。
- 小哨页优先呈现具体关注；后台正常时收起技术细节，异常和授权不足时提供对应处理入口。
- 到货与断货继续共用「增加提醒次数」按钮，分别显示余额与授权结果。
- 历史页以条件和结果为主；我的页突出会员有效期、价格和名额，长说明按需展开。
- 我的页头改为紧凑账户卡，品牌、身份状态和用户编号集中呈现；复制按钮保持清晰的触摸区域，减少无用途留白。
- 浅色与深色使用一致的层级、圆角和动作样式，保留绿色哨子、玻璃导航与黑金会员标识。
- 新增「我的 → 更新公告」入口，按版本列出已登记的主要变化。缺少具体更新内容的版本标记待补充，不推断正式发布日期。

## 可靠性修复

- 根据微信基础库 3.17.3 的 `Free data selection` 警告，查询与历史页面的选择状态改为在 `onLoad` 同步阶段按实例初始化，避免注册复杂自由数据；仍不经过 `setData`。分别覆盖多实例数组隔离与账户离线时的目录加载。
- 旧提醒反馈核对商品、完整门店范围与关注更新时间，防止误停后来修改的关注；目标不匹配的旧消息只记录反馈。
- 保存、暂停和删除结果与后续刷新结果分开处理，刷新失败不会把已确认写入显示为失败。
- 自动刷新保留关注排序与展开状态；失效缓存要求重新核对，避免界面范围和实际请求不一致。
- 配置面板与兑换弹窗独立控制导航可见性，覆盖键盘关闭、导航延迟挂载及弹层关闭后的恢复。
