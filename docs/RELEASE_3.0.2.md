# 果小哨 v3.0.2 发布说明

本地候选。未部署云函数、未上传、未提审或正式发布。线上服务端仍为已发布的 **v3.0.0**；本次只改消费者前端、云函数配置校验与本地版本对齐（配置校验需重新部署 `gxs_api` / `gxs_monitor` 才在云端生效）。

## 问题一：安卓订阅授权被拒后无法恢复

安卓微信在用户勾选过「总是保持以上选择」+「不允许」后，`wx.requestSubscribeMessage` **不再弹窗**，直接返回 `reject`。界面原先只显示「到货未授权，断货未授权」，用户找不到恢复入口。另外，**剩余提醒次数不等于微信当前允许接收**。

### 修复

1. **拒绝态可恢复**：识别 `reject` / `ban` / 总开关关闭；关注页与「我的」展示「微信提醒权限未开启」状态卡；主按钮「前往微信设置」调用 `wx.openSetting({ withSubscriptions: true })`，返回后重读权限。部分拒绝不挡全部。
2. **授权与余额分开**：到货权限已拒绝时不再显示「已就绪」；设置中的「允许接收」不会自动加次数，仍须点「补充提醒次数」由微信 `accept` 记账。
3. **弹窗调用链**：`wx.requestSubscribeMessage` 在点击同步栈内以 `success`/`fail` 回调发起，30s 超时防卡死；不再从 `showModal` 成功回调发起授权。

## 问题二：首页维护公告过期仍展示

截图 23:56 仍显示「预计今晚 20:20 结束」。原因是 `announcement` 仅支持字符串或 null，无到期时间。

### 修复

1. **配置结构**：`announcement` 兼容旧字符串，或对象 `{ text, kind, startsAt, expiresAt }`。到期自动隐藏；整对象替换写入，避免残缺补丁残留旧文案。
2. **服务端过滤**：bootstrap 下发前丢弃已过期/未开始的结构化公告。
3. **查询页状态横幅**（优先级）：
   - 有效公告（未过期）
   - 微信提醒权限未开启 →「前往微信设置」
   - 接口实际异常 → 显示异常状态，**不**宣称已恢复
   - 无事不显示横幅
4. **过期文案**：只隐藏，不推断「查询已恢复」；若接口仍异常，改显示实际异常状态。

### 运营操作（本次过期文案立即下架）

管理员小程序 → 配置管理 → `announcement` 设为 `null` 后保存。用户重新拉取配置即消失。**不需要**为清文案单独发小程序版。

后续维护公告建议写成：

```json
{
  "announcement": {
    "text": "苹果官网维护中，预计于今晚20:20（北京时间）结束。届时果小哨将第一时间同步恢复查询功能，实际恢复时间以苹果接口状态为准。",
    "kind": "maintenance",
    "expiresAt": "2026-10-16T20:20:00+08:00"
  }
}
```

恢复后可短暂发 `kind: "recovery"`、`expiresAt` 为 2 小时内的短公告，到期自动消失。
