## 设计取舍

参考《果小哨 UI 体验升级项目规划书 v1.0》，以“选配置 → 看门店观测 → 关注变化 → 接收提醒”为主线。优先减少常驻长表单与重复说明，避免再增加一层“购物计划”概念。

- 查询、历史、小哨复用原生底部配置面板。页面显示已保存条件，面板承载本次草稿；明确保存后才改变条件，打开面板不会查询、扣次数或写关注。
- 查询首屏保留配置、门店、主查询动作和直接关注路径。规则可展开，收费、免费体验和新品限制仍有明确提示。旧查询结果继续标记原配置与时间。
- 小哨页以具体关注卡为主。健康状态正常时弱化技术细节，需要处理的异常给出对应动作；授权不足时提前显示授权入口。到货和断货保留同一个按钮、分别显示余额。
- 历史页先显示条件、结果与记录，最近浏览作为恢复入口放到次级位置。无记录、未知和缺少采样证据继续明确区分。
- 我的页突出有效期、价格、配置名额和微信授权条件；已有会员的续费入口改为次要动作。未完成订单、查询支付结果、继续支付、放弃订单、兑换和退款记录保留。
- 使用中性浅背景、实体白卡片和绿色主动作，深色模式使用对应的高对比颜色。保留现有哨子标识与透明浮动导航。黑金仅用于会员标识。

本轮未增加多颜色计划、门店矩阵、连续库存时间轴或新提醒偏好。它们涉及持久化、额度、历史覆盖及兼容设计，不能只靠前端并排展示就当作完整功能。

## 一起修复的交互问题

- 旧提醒“买到了”只凭 `followId` 暂停，可能误停后来编辑的新配置。新任务保存 SKU、完整门店集合及关注更新时间，反馈和条件暂停在同一事务内完成；缺少可靠快照的旧提醒只记录反馈。
- 同一毫秒的连续编辑也递增关注更新时间，避免“改走再改回”被旧提醒误认为原目标。
- 暂停、删除或保存已经成功时，后续列表读取失败只提示刷新失败，不再把已确认写入说成失败。
- 自动刷新保持已有关注顺序及展开状态，编辑一项不再将卡片挪到列表末尾。
- 配置面板与兑换弹窗占用独立导航隐藏状态，收起键盘不会使底部导航重新出现；导航延迟挂载也读取当前弹层状态。
- 失效或损坏的缓存门店保持待核对状态，阻止按错误条件继续查询；不会悄悄转成全部门店。
- 保存同步读取最后一次选择；退出脏草稿要求明确放弃，保存中阻止重复提交与退出。系统返回使用原生 `page-container`，平台交互仍需真机验收。
