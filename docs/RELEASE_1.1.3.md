# 果小哨 1.1.3：审计修补

## 本轮结果

已在原项目完成代码、独立运营项目、测试及云函数更新。用户前端尚未上传、提交审核或发布。支付保持暂缓；共享兑换码继续按既有活动规则提供会员能力，没有轮换或取消。

### 查询与上游保护

- 手动查询与自动监测共用数据库事务预算，关闭手动路径绕过分钟/每日限额的漏洞。
- 新实时查询每账号默认过去 60 秒最多 6 次、同时 1 笔，会员也遵守保护；相同 ID 的结果重放不重复计次。
- 429/503 及失败突增触发共享暂停，遵守 Retry-After，冷却后只允许一个有效探测。多个实例、旧请求迟到、探测过期及接管都已测试。
- 主动拒绝不写伪观测；全量失败返还使用次数，部分成功明确提示未成功的门店和重试时间。
- 补上失败响应无商品字段时的页面容错，避免失败处理再报错。
- 自动采集健康统计排除未发出的预算拒绝请求。

### 管理权限与上传包

- 管理员名单只能通过可信运维身份更改；名单管理员不可自助扩权。
- 配置修改在同一事务追加脱敏审计，审计失败则修改也回滚；提交前重新核对最新授权。
- 删除闲置的裸 OPENID 管理分支，只保留带 AppID 的用户身份。
- `miniprogram/` 只有查询、小哨、历史、我的四个页面。管理源码、路由已移至独立 `tools/admin-miniprogram/` 项目，使用已有资源方 AppID，未增添授权白名单。

### 构建与版本

- 监测包从 API 的规范源码按真实依赖生成，33 个旧共享文件改为 25 个；生成源码 141,473 字节。新增保护逻辑已包括在此数字内。
