# 果小哨 v1.5.1 发布说明

记录日期：2026-10-01。状态：**本地发布包已就绪，可进入人工部署与提审**。消费者前端已通过微信开发者工具预览编译，实际预览包 651017 bytes；本轮云函数尚未部署、微信开发版本尚未上传、尚未提交微信审核。线上已生效的是 1.5.0 的 2026-10-01 容量紧急修复，不将其验收结果写成本候选已上线。

维护者已确认：**在容量整组标准未达标的情况下照常推进正式发布**，并把缺口原样写入本说明与验收状态；不把 `productionAcceptancePassed` 改成 true，也不把返回“稍后再试”计作 300 人承载成功。

## 本版修复

- 继承持续容量、目标复用和旧午夜等待恢复，避免日计数耗尽后停到午夜；保留真实限流、断路器和会员零扣次。
- 相同目标的并发等待覆盖正常慢上游响应，避免 300 名会员查询相同目标时 299 人过早收到“刷新中”；仍限制总等待、数据库轮询和实际采集次数。
- 支付和查询成功后的执行锁清理异常不再覆盖已经持久化的业务成功结果；原权限错误及失败退款保持正确。
- 修复订阅旧次数池与在途发送、授权、退票竞争造成的虚假可用次数。
- 页面晚响应不能清除另一笔请求的重试编号，不能覆盖新会员状态或写入已经销毁的页面。
- 会员生效后清除旧免费权限提示；真实繁忙保留，过期会员界面重新对齐服务端状态。
- 提醒发送前重新核对库存、会员、关注、推送开关、时效及任务租约；已失效的旧提醒不外发，明确未发送时退回授权。
- 业务健康按各组成功且持久化的观测判断，识别“心跳正常但库存不更新”，提供可配置平台告警的结构化日志。
- 异常未来库存以可信新样本恢复，不伪造补货或确认；异常未来 checkpoint 不能让健康状态永久停留在预热，真实限流截止时间保持有效。
- 新增显式持续有货复查配置，解决原变化后二十秒即退出加速的逻辑缺口；默认关闭，须以常驻采集和容量验收配套开启，源码支持不等于生产达到每三秒。
- 新常驻有货模式下，慢提醒发送不会让采集等待发送队列；发送保持串行、有界唤醒及失租保护，停机等待在途发送结束。
- 运营配置保存携带版本，服务端拒绝缺版本的旧客户端及陈旧保存，旧编辑器不能无意把已修复的容量模式写回。仅可信云端运维脚本保留无版本兼容。
- 三云函数、消费者前端和常驻采集候选使用 1.5.1；新增实际下载云包的内容比对，避免只凭版本号验收。

具体复现、交叉审查、依赖风险与验证结果见 [1.5.1 审查记录](AUDIT_1.5.1.md)。用户可见更新公告已登记，但公告不表示候选已经正式发布。

## 300 人目标与已知缺口

维护者确认要求：**至少 300 人同时点击查询、全部关注每分钟检测一轮、有货时每 3 秒复查状态**。相同目标共享成功只证明去重场景；不同目标会消耗不同的新采集请求。当前容量和分钟定时运行方式没有达到整组标准，不能把返回“稍后再试”计作成功，也不能简单调大保护参数来承诺扩容。具体下界、架构差距和验收顺序见 [容量与检测频率验收](CAPACITY_ACCEPTANCE_1.5.1.md)。

**本次发布接受上述缺口继续推进**，缺口保持可见：

| 交付标准 | 当前状态 | 发布时如何表述 |
|---|---|---|
| 至少 300 人同时查询全部成功 | 未达标。离线不同目标仅约 59/300 完整成功，其余繁忙 | 不承诺 300 人即时全成；繁忙计为繁忙 |
| 全部关注每 60 秒检测一轮 | 未达标。18 组约需 25920 次自动请求/日，分钟定时仍有空档 | 不宣称每分钟全覆盖 |
| 有货时每 3 秒复查 | 未达标。全持续约需 518400 次自动请求/日；`availableIntervalSeconds` 默认 0 | 源码支持不等于生产已按 3 秒运行 |

已有模拟压测不覆盖真实云数据库事务争用、云函数并发配额、SDK 延迟、数据源限流和成本。原默认全站持续补充约 6.94 个上游请求/分钟，最多积存 60；一次查询最多三家门店，和“300 位用户”不能直接换算。真实达标验收仍须在代表性门店/商品分布下单独完成并另记证据。
