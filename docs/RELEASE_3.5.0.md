# 果小哨 v3.5.0 发布说明

2026-10-30 开始的本地开发候选，基于 `7cc3827`。维护者确认先做「我的小哨」与手动到期提醒免费试验，并要求继续同步 Apple 新品与完整可观测配置；最新确认库存查询继续作为首页，「我的小哨」位于第二个入口。此记录不是部署、上传、提审或正式上线证明。

## 用户更新小结

首页继续查询库存，我的小哨集中查看关注与到期事项。新增免费到期提醒试用，保存事项与微信授权状态分开显示。补齐 Mac Studio 定制配置参考；定制款不支持门店取货，标准配置查询不受影响。

## 产品范围

- 库存查询为默认首页，四个原生入口依次为查询、小哨、历史、我的，保留精确 SKU 和无需先查询的直接关注。「我的小哨」展示真实库存观测、已有提醒记录入口和未来已授权的到期计划；不会将页面下次读取当成下次库存通知。
- 到期事项独立于 Apple 目录与会员资格。支持会员续费、优惠券、保修到期、活动截止和其他事项；填写名称、到期日期、提前 0–365 天、北京时间提醒时刻，最多保存 20 项。新建、编辑、删除、重试与授权均有真实事件路径。
- 保存和授权是分开的动作。源码已按后台「日历事件提醒」模板配置 `thing3/time2/time6/thing7/thing5` 五个字段，但发送开关仍为关闭，未就绪时显示「仅保存，微信提醒未开启」；修改内容或日期后需重新授权。授权只对一条事项的一个修订生效，不消费库存通知授权。
- 更新提醒后续只考虑少量已核实来源；跨品牌蹲货后续先验证一个来源；截图识别需用户确认日期。本版没有这些入口，也没有以这些未来能力收费。

参考 [Distill 官方工作原理](https://distill.io/docs/web-monitor/what-is-distill/) 的按计划读取来源、比较内容和条件通知思路，采用的是后续产品边界，不引入任意链接采集。用户是否愿意付费仍待真实试用验证。

## 可靠性与用量

- 使用独立 `gxs_deadlines` 集合，用户身份来自服务端上下文；用户之间隔离，所有客户端写操作携带预期身份，修改与删除检查修订号。
- 新建使用稳定操作编号。创建、修改、删除及授权可恢复原操作；前端在请求开始前保存恢复记录，保存中同时锁住输入和处理函数，超时后复用原操作，不盲目重复创建或弹授权。
- 定时调度与 Apple 采集 lease 分开，可信分钟触发器按索引读取到期记录，每轮最多处理 5 条待发与 5 条过期发送锁。发送前事务重新读取用户设置、模板、修订和服务配置，不扫描所有用户，也不缓存发送资格。
- 调度不保证秒级或准点。通知开关、免打扰、队列积压和服务故障可能延后；超过到期日不再发送。微信受理不等于实际收信。发送结果不确定或发送锁过期时不自动重发，防止重复通知。
- 默认关闭时增加一次运行配置读取；开启后增加有界到期查询及按实际到期项发生的事务读写和发送。「我的小哨」到期列表仅进入该页面、返回或手动刷新时读取，不进入库存轮询，也不因查询首页启动而读取。Apple 的采样间隔、unknown 覆盖及目标集合不因本功能减少。无真实账单降幅结论。

## 数据与回退

数据库计划新增私有 `gxs_deadlines` 及到期/发送锁/用户列表索引；账号索引与授权回执复用私有配置集合。旧关注、库存、付费和授权记录不迁移。删除事项释放 20 条名额并移除标题、日期等正文，仅保留最小幂等墓碑；发送结果不确定的历史项仍允许管理。

上线顺序：按更新后的数据库计划确认集合和索引，部署同版 API 与 monitor，再验证客户端。2026-10-30 12:47–12:48 已针对用户报告的缺表故障补建 `gxs_deadlines`、设置 ADMINONLY 权限并创建三条复合索引；12:48:15 的自然请求已成功读取空列表。该次实际修复仅涉及数据库结构，不包含函数重部署。后台「日历事件提醒」模板 ID 与五个字段已从截图核对并写入源码默认配置，`enabled` 仍为 `false`；存量云端配置、同版函数、发送方凭据、用户授权及真机收信全部验证后，才可单独开启 `deadlineReminders.enabled`。

回退时先关闭 `deadlineReminders.enabled`，观察正在发送的任务结束或进入不确定态，再回退客户端与函数代码；保留新集合和幂等回执，不批量删除数据，不重置不确定发送记录来重试。旧 Apple 路径继续使用原集合及规则。
