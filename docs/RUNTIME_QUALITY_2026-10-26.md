## 1. channel-video 为什么仍然出现

历史上曾把平台报告中的名称当作业务组件并添加空占位；后来已删除。源码清理解决了错误添加的组件，却不改变微信内置组件注册和质检过滤逻辑。这一项此前一直保持 open，不能把此前的本地修补或普通真机使用正常扩写成微信质检通过。

本轮在 **3.16.1、3.16.3、3.17.3、3.17.4** 四版官方基础库上重新验证：

- 空白页面不加载果小哨 JS/WXML，`__wxAppCode__` 为空。
- 基础库同时注册内置 `channel-video` 和 `wx-channel-video`。
- 原样执行各版本的未使用组件审计回调，均报告 `pages/empty/index` 存在 `channel-video`，数量 1。
- 四版审计回调相同，仅以 `wx`、`exparser-inspector` 等前缀排除内部组件，漏掉无前缀别名。
- 每版四组对照均通过：普通内置组件排除、无前缀别名报告、真正未使用业务组件报告、已实例化业务组件排除。

这建立了无需业务声明也能产生该告警的独立证据。它支持平台审计缺陷的机制，不能改写任务 14190 的实际失败结果。当前未发现有效且不操纵质检的业务配置修复入口；没有添加假组件、隐藏播放节点、修改 SDK/注册表、关闭审计或切换渲染引擎。

精简证据：[四版官方 SDK 空页复现](../evidence/verification/3.4.0-runtime/channel-video-sdk-reproduction.json)。完整 SDK 仅保存在忽略的本地 output 下；官方包来源、原文件哈希、原审计输出和对照结果保存在精简 JSON 中。

## 2. too early 的精确 SDK 溯源

从本机开发者工具的官方索引取得原版 3.16.3，包内版本文件与用户错误详情一致。截图中 10 个列号均与该版本 `WAServiceMainContext.js` 的调用链吻合。

- 桥接器在内部生命周期尚无 `start` 时，对非白名单 API 返回 `<api>:fail too early`、`errno: 4`。
- Promise 失败适配器去掉 API 前缀，再构造 `Error('too early')`。这解释了错误列表为什么没有具体接口名。
- SDK 正常入口顺序为 `start → postStart → execEntryFile`。不能只凭此堆栈判定是业务代码还是 SDK 内部预加载路径发起，也无法从通用 invoke 参数反推出 API 名。

精简证据：[原版 3.16.3 静态定位](../evidence/verification/3.4.0-runtime/sdk-too-early-origin.json)。尝试执行独立 VM 片段时被自动审批以 `blocked by policy` 拒绝，未绕过；该项明确只有静态分析，不计为动态重放。

本轮修补给业务导航补上明确失败处理，并保留原生接口名和错误码；这消除了已复现的业务缺口，但没有证据宣称它根治了这次平台预启动异常。没有添加全局延时、重写微信生命周期或按 `too early` 文本过滤错误。

## 3. 已复现并修复的业务缺口

位置：`miniprogram/utils/navigation.js`、`utils/tab-bar.js`、`utils/journey-context.js`、各页面导航入口与 `app.js`。

- 指南等入口直接调用原生导航，绕过原有 tab 锁。修前双击指南入口再点 Tab 可产生三次原生导航；修后所有程序化跳转共享同一把锁，原生完成或目标页到达释放，旧完成回调不会释放新请求。
- 直接导航缺少显式失败回调。现在统一处理失败、同步异常和返回 Promise；原生回调与 Promise 同时触发时，只结算一次。失败后用户可主动重试，不自动重放导航。
- “返回原通知体验”以前在导航成功前消费返回意图。现在仅成功时消费；每次意图有独立代次，旧成功回调不能清除后来重新建立的同 URL 意图。
- 底栏显示/隐藏保留原有有限重试，补齐返回 Promise 的成功/失败处理，避免回调已处理失败却遗留未处理拒绝。
- `[gxs] navigation_failure`、`[gxs] native_tab_bar_failure` 记录具体 API、去参数页面路径与有限数值错误码。App 异常与 SDK 超时记录均补上时间、版本、前后台状态及最近导航上下文，不为取诊断信息额外调用原生设备接口。
- `too early`、`routeDone` 仍保留为错误。仅明确 `-601008` 且全部为 SDK 栈的自定义重复报告沿用警告分类，不改变微信自身的错误采集。

针对导航并发、失败重试、双通道回调、旧回调、返回意图、错误上下文的回归随补丁加入。独立审查发现的同 URL 意图竞态已修复并增加完整复现测试。
