使用攻略和提醒测试由各自的分包加载专用脚本，原来的页面入口仍可使用。微信官方工具的本地代码质量扫描 11 项全部通过，上传后仍需完成体验版及微信后台复测。

微信截图中，主包大小和组件两项通过，JS 文件一项指出两个主包未使用的文件。以 v3.8.7 源码核对，攻略页和提醒测试页已拆入分包，它们独用的两个模块仍放在主包中。

## 本包验收

使用微信 `miniprogram-ci@2.1.31` 的 `checkCodeQuality` 对两个版本分别扫描。v3.8.7 的 `CONTAINS_OTHER_PKG_JS` 返回了截图中的两条原路径，共 7,831 字节。v3.8.8 的这一项返回空列表、0 字节，主包大小和组件项也通过。本地主包源码从 1,353,169 字节降至 1,345,338 字节；另行编译后，按主包目录统计的编译文件合计从 1,184,663 字节降至 1,177,749 字节。

使用微信开发者工具、基础库 3.17.6 在隔离工程中从两个旧地址分别启动页面，验证了攻略切换阶段、展开常见问题、打开提醒测试和返回。模拟微信已受理的测试记录正确显示已授权、已受理和待查收，全程无运行错误。本轮未实际发送订阅消息。

全部 2,211 项自动化测试通过。发布检查现在会报告仅被分包使用的主包脚本，并指出引用它们的分包。另修正了「我的」离线界面检查沿用的旧标题，使其与页面上的「剩余查询次数」一致。

## 微信复测

1. 上传前重新编译 v3.8.8，在微信开发者工具运行「代码质量 → 主包」扫描，核对 JS 文件、主包大小和组件三项。
2. 在体验版分别从原入口首次打开使用攻略、提醒测试，确认攻略内容和提醒进度可见。
3. 发布检查的 68 项中已通过 67 项。剩余一项需要本版对应的微信复测记录，涉及 `channel-video` 未使用提示、首次切换底部导航、商品图片大小和图片格式。

仅处理本次打包提示无需部署云函数或迁移数据。若上一版的三站会员查询提示尚未上线，仍需部署包含该能力的 `gxs_api`。回退时可恢复上一版小程序。
